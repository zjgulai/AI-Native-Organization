# ADR-0014：管理层决策权平面，而非Agent层级

状态：设计已形成。MGT-Q1至MGT-Q3 已由 D-065（2026-09-19）关闭；仍待用户确认者为 MGT-G8、MGT-G9、MGT-Q5。日期：2026-09-18。
适用范围：AI组织变革项目的管理层设计。**本ADR的"决策权平面"决定与全部边界保持不变**；管理层编制由v1的9岗位改为**v2的3岗位**（1个CEO + 2个二级负责人：增长官、治理官），该结构变更见D-062。
关联决定：D-021、D-022、D-024、D-029、D-056、D-057、D-053、**D-061、D-062**。

## 背景

v2.3 已确认 50 个可独立寻址的岗位分身、8 条价值流、20 个候选场景与八阶段产物门禁协议。该协议解决了「一件事如何被正确地做完」，但没有角色承接**组合层的取舍责任**：多个 Case 争抢同一账号、商品、预算与时段时无人裁决；装配规则与风险阈值有维护者却没有版本所有者；8 条价值流之上没有人对组合结果负责。

用户据此要求在 50 个岗位之上增加一层二级负责人与一个顶层 CEO；v1设计为8个CXO，用户随后决定不采用该数量，改为2个二级负责人。这与既有 D-022「全部 50 个岗位不设置上级 Agent」表面冲突，因此必须明确该决定的作用范围，并确定管理层的正确形态。

外部证据同时给出两个方向相反的约束：AI 正在被用于削减中层管理（Gartner 预测到 2026 年 20% 的组织会借此扁平化，削减超过一半中层岗位；2022–2025 年上市公司经理人数下降 6.1%），而中继职能被移除后其职责会向上堆积并常常无人接手（Korn Ferry 2025：37% 员工感到方向不清，近一半高管怀疑无力管理堆积的事务）。同时，多智能体架构的实测成本约为单智能体 token 消耗的 15 倍，其收益集中在可并行的研究型任务上。

## 决策

1. **D-022 的作用范围被明确限定在执行面。** 「不设上级 Agent」指任何 AI 岗位不得通过 Agent 调用、会话或权限转授去管理另一个 AI 岗位。管理层不是执行面上的上级 Agent，而是**决策权平面**：它通过版本化契约与资源配额生效，从不通过调用或对话生效。
2. **管理层职能被限定为四类决策权**：标准所有权、资源配额与优先级排序、组合取舍、升级与冻结。转述、催办、叙述性汇报、单张 Case 的阶段推进与方案编写被明确排除。
3. **采用 1 + 2 结构**（v2，见D-062）：MGT-001 CEO 与 2 个二级负责人——MGT-002 增长官（覆盖 AGT-001~004、AGT-006~039，共38岗）与 MGT-003 治理官（覆盖 AGT-005、AGT-040~050，共12岗）。两域并集覆盖 AGT-001~050 全部 50 个岗位，**无遗漏且双线归属为0**。

   本节在v1中曾写作"采用 1 + 8 结构"（CEO + COO/CFO/CMO/CTO/CRO/CAIO/CCO/CQO）。该结构**不再有效**，且其5处岗位双线归属（AGT-002/018/027/038/044）在v2中已消除。
4. **管理层不参与 Case 生命周期。** 管理层不得作为 Lead 或 Worker 出现在任何 Case 中；唯一例外是阈值触发的升级，此时管理层作为接收者出现，不改变 Case 的 Lead、阶段与顺序。这不改变 D-057 关于 External Case Control 为唯一编排责任方的结论。
5. **信息流单向且聚合。** 执行面写 Case/Event Ledger；管理层只读聚合指标、异常队列、资源冲突清单与已验收产物摘要，不接触业务系统原始数据、客户明细、凭据与未验收产物原文。管理层的可见面窄于任一数据与平台岗位。管理层按日/周/月/季节拍离环运行，不做实时在环。
6. **新增第六类契约。** 既有五契约（Business、Skill、Runtime、Access、Assurance）描述一个岗位如何正确地做事；新增**管理域合同 MDC**（域范围、成员岗位、标准版本引用、资源配额、风险阈值、升级规则、组合目标、评估口径，由该域 CXO 拥有）与**全局约束合同 GOC**（跨域约束、全局配额包、优先级排序，由 CEO 拥有）。两者均为版本化、不可变、带 Hash 的发布物，由模型外 Case Control 与 Policy Gate 读取。管理层只能提出与决定哪一版进入下一状态，不能自发布。
7. **决策按阶梯归属**（v2为六级）：L0 自动化（已发布规则内的判定与执行）、L1-G/L1-V 域内（增长官／治理官）、L2 跨域（CEO）、**L2b 自涉争议（真人所有者）**、L3 呈报（CEO 形成建议，真人所有者批准）、L4 专属真人所有者（资本与预算终审、组织与人事变更、法律与对外承诺签署、最终停止确认）。没有归属的事项视为未授权，默认 HOLD。

   **L2b是v2新增级，且不可省**：合并后指标口径的提出、维护与被评估集中在治理官一个身份，而CEO的排序输入正是该口径；若把这类争议交由CEO在L2裁定，等于用争议标的本身去裁决关于该标的的争议。
8. **管理层内生退出条件。** 若某管理岗位连续两个季度无法在决策周期、组合偏差、例外升级率三项中改善至少两项，该岗位进入 `MGT_REVIEW`，候选处置为合并域、降级为制度岗位或撤销。管理层不是永久结构。
9. **独立控制的独立性被显式保护，且v2将其从"角色隔离"升级为"权限隔离"。** v1由MGT-006 CRO持有独立控制域的产能与标准，对AGT-005/043/044/050的结论不得以经营或效率理由改写。v2中该职责并入MGT-003治理官，而治理官同时持有指标口径的提案权与排程权，因此独立性不能只靠角色分离，必须落为三条机制：①指标口径的冻结权归AGT-005与外部复核，治理官只有提案权，冻结记录签署方不得含MGT-003；②涉及治理官自身评估尺度的争议走L2b真人所有者，不经CEO；③AGT-005的复核结论直达CEO与真人所有者，**不向治理官汇报**，治理官不得修改、延迟、归档或压后。

   依据：AWS Well-Architected Agentic AI Lens 要求控制「**enforced at the control-plane boundary … rather than relying on agent self-restraint**」。因此**若目标Host只能通过Prompt层表达上述隔离，MGT-003不得进入Shadow阶段**——提示词中的约束不构成服务端权限控制。

## 选择理由

- 保留 D-022 的实质（AI 岗位不互相管理、不转授权限、不通过对话决策），同时补齐组合层取舍责任，避免把全部跨域冲突堆给真人所有者一人。
- 排除信息中继是唯一能同时满足「加管理层」与「消灭人为低效沟通」两个目标的设计；管理层若转述下级汇报，就是用 AI 重建刚被协议删除的中层。
- 只读聚合视图使管理层权限面窄于执行面，从机制上消除高层越权读取全量数据的风险，并与 D-056 的最小权限方向一致。
- MDC/GOC 让管理层的决定可审计、可回滚、可版本比对，而不是留在会议记录与口头指令中。
- 内置退出条件使这一层可被判定为冗余，避免组织结构因不可撤销而长期存在。

## 弃选方案

- **管理层作为消息中继（CXO 汇总岗位汇报、CEO 汇总 CXO）**：引入最多三跳延迟，且每次转述都会丢失证据并引入幻觉，等于用 AI 重建被删除的中层。同时违反 D-024/D-053 的无隐式会话约束。
- **管理层持有直接 Case 指令权**：破坏单 Case 结果责任与确定性装配，使 Case 的 Lead 与阶段可被外部改写，导致验收与回滚失去唯一事实归属。
- **管理层持有 Action Intent 或策略模板提案权**：把决策权与资产动作权重新耦合，与 D-029 的模型外裁决边界冲突；本设计因此不授予该能力。
- **v1的"8 个 CXO"方案**（本节在v1中的原文为"只设 5–6 个 CXO 或设 10 个以上……8 个在管理幅度与覆盖完整性之间取得平衡"）：**该理由已被撤回**，原因有三——① 它引用的是"管理幅度"直觉，而本轮核实发现 Fayol「不得超过6名下属」**找不到任何原始文本支撑**，Bloom/Lemos/Sadun/Van Reenen 系列**没有管理幅度经验发现**；② 它未计入8-CXO结构自身的代价：5处岗位双线归属（矩阵式双汇报）；③ 用户明确选择减少协调面。改采3岗结构（D-062）。
- **单一通用管理Agent（不设二级负责人）**：**未被弃选，而是保留为待验证的对照臂**。已核实的一手受控实验测得单 agent 基线准确率超过约 **45%** 后增加 agent 出现负回报（β̂=−0.404, p<0.001），而本项目**没有管理判断的正确性基线**，因此无法排除"一个通用管理Agent已足够"的可能。该对照臂由 `MGT-EVAL-R0` 门执行（见[影子验证设计](../04-organization/management/SHADOW-VERIFICATION.md)§6.1）；不做该对照臂，3岗结构就无法被反证。
- **把管理层做成一个新的 Agent 编排层**：直接违反 D-057，并把多智能体架构约 15 倍的 token 成本乘到整个组织上。

## 影响与后续

- v2新增 **3 份** Soul Contract、3 份 Role Playbook、3 份管理岗位档案与 3 份 Preset Blueprint；不改变 AGT-001~050 的编号、契约与资产索引。（v1曾生成9份同类资产；因编制改为3岗，v1的 MGT-004~009 六套资产已删除，且当时未进入版本控制，无历史版本可回滚。）
- 五契约管理图与 50 岗位资产管理图需要增加 MDC/GOC 的引用关系；`ORGANIZATION-MAP` 需要增加决策权平面视图。
- 管理层只读聚合视图需要独立的口径、质量与审计契约，属 RP-M1/RP-M3 范围；在该契约核实前，管理层的全部输入能力为 unknown。
- 影子试验：v1建议从9岗中先做3个代表岗位（CEO + COO + CAIO）。v2只有3个管理岗位，**代表子集不再成立，3岗位全部同时先验**，并新增 `MGT-EVAL-R0`（结构必要性对照臂）与 `MGT-EVAL-R2`（独立性复审）两道门；影子结果不等于生产授权。
- 本 ADR 不授权任何企业系统连接、写入、资金动作、人事决定或生产自治；当前 3 个管理岗位均未实例化，`production_authorized=false`。
