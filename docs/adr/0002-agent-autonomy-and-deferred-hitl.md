# ADR-0002：Agent-first自主闭环与后置HITL

Status: superseded in part by [ADR-0003](0003-single-case-agent-with-role-skills.md), 2026-09-11

保留有效的决定：初始运行不把真人负责人或HITL设为常规节点；所有外部动作仍受业务控制、回执与恢复约束。第1项“AGT-002动态组建多Agent任务组”及其相关运行语义已由ADR-0003替代。

## Context

原v1.0框架把真人业务负责人和人工接管设为每个场景的常规运行依赖。用户随后明确：50个数字分身自行匹配，覆盖管理和运营全链路；可通过MCP、tools、API、hooks直连系统；初始不启动真人负责人，HITL在运行后再补。

这不是简单减少审批节点，而是改变运行主体：常规闭环由Agent任务组完成，系统和策略定义可执行边界。仍不能把提示词、会话日志或工具UI当成权限、业务事实或外部动作回执。

## Decision

1. 采用Agent-first运行模式。AGT-002按场景、业务范围、能力、数据、工具、负荷和独立复核需要动态组建小型任务组；每个工单有唯一AI结果负责人。
2. 初始工单不要求真人负责人、人工批准或HITL作为常规状态节点。HITL是未来可启用的运行模式，不能以“后置”解释为已批准或永不需要。
3. 每次工具动作仍必须由业务控制层或受控目标系统校验范围、策略版本、参数、幂等键、有效期和回执。无适用策略、外部状态不明或恢复条件缺失时，只冻结受影响范围并写入自治异常账。
4. 有物理、专业资质、法定身份或外部签署要求的工作，Agent仅能通过已配置的受控系统、供应商或合格执行主体发起并获取回执；Agent人格不产生法人、签署或专业资格。

## Considered Options

- 保留真人业务负责人作为每张工单必经节点：责任表述直接，但违背用户希望先由50个分身完整跑通链路的方向，并保留决策等待。
- 完全放弃策略、回执和异常冻结：表面上最自主，实际不能区分成功、重复执行和越界动作，无法形成可核对闭环。
- 让Harness会话同时承担身份、控制、审计和恢复：与[ADR-0001](0001-harness-execution-and-business-control.md)冲突，也没有当前证据支持。

## Consequences

50岗位从“辅助真人部门的角色表”改为“可动态编队的责任系统”。既有193/46个Agent规划应被归并为可复用技能、知识和工具，而非与50个长期角色并列扩张。

此决定不授权生产系统连接、对外发送、资金操作、商品/库存写入或组织变更。目标Harness版本、接口和动作策略经核实后，才可产生实际配置和运行证据。
