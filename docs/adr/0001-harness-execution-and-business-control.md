# Harness执行与业务控制分离

Status: accepted, 2026-09-11

DeepSeek Harness承担岗位会话、技能调用和受控工具执行；持久场景工单、动作策略、幂等、动作回执、自治异常与恢复由现有业务系统或最小补足的业务控制层承载。这样选择是因为本机已核实的Harness工作流不能单独证明跨天业务动作可恢复或可追溯，而将这些约束只写进提示词会使账号、预算和实际副作用失去可靠边界。

## Considered Options

- 让Harness同时承担聊天、任务状态、审批和全部业务控制：实现看似更快，但持久性、恢复与动作边界无法仅凭当前已核实能力保证。
- 同时部署五个参考项目：会重复维护身份、工作项、权限、记忆与结果，并扩大许可和集成复杂度。
- 新建完整企业Agent平台：可能成为第二套业务系统，首个经营闭环之前投入过大。

## Consequences

任何生产配置都必须连接到可检查的工单、动作策略和回执，而不是把Agent会话日志当成业务事实。目标部署与业务系统清单确认后，才决定适配器、数据契约和实际配置；本ADR不授权生产动作或选定数据库、云环境与具体产品。初始不要求人工接管作为常规路径；后置HITL的取舍见[ADR-0002](0002-agent-autonomy-and-deferred-hitl.md)。
