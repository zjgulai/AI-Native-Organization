# 系统接入资产盘点与优先级

状态：依据《公司平台和系统全景图（2026-09快照）》形成的连接候选清单。资料显示系统或规划存在，不证明接口、凭据、读写权限、数据质量或目标Harness兼容性已经通过验证。

## 可用资产与证据边界

| 资产 | 材料中的状态 | 对50 Agent的潜在作用 | 当前仍需核实 |
| --- | --- | --- | --- |
| RootData 路特数据平台 | 上线 | 跨链路经营事实、指标和数据治理的读取候选 | 数据域、口径、刷新、服务身份、查询边界 |
| Amazon Seller Central | 上线 | Amazon经营、商品、账号健康和广告事实/动作候选 | SP-API或其他接口、账号范围、限流、动作权限 |
| 数智星图 | 在建 | 销售、广告、库存和财务经营视图候选 | 是否可供Agent读取、指标权威性、交付时间 |
| 自研ERP | 上线 | 订单履约、财务会计、供应主数据的权威记录候选 | 接口、幂等、采购/库存写入和回执 |
| PLM / QMS | 上线 | 产品、BOM、变更、质量证据和准入候选 | 主数据映射、变更/质量事件动作能力 |
| WMS / TMS | 上线 | 库存、履约、退货和物流回执候选 | 仓库/运单范围、事件粒度、补偿路径 |
| Shopify | 上线 | 独立站经营、商品、内容和转化候选 | 店铺身份、客户数据范围、写入和回执 |
| CRM / KOL /增长系统 | 混合上线、在建或规划 | 留存、触达、达人和内容运营候选 | 系统身份、隐私边界、策略和外发能力 |
| 品牌AI平台（DSH base） | 在建 | 角色、技能、工具和运行资产的目标承载候选 | 实际版本、profile、插件、配置schema、运行环境 |
| 既有Agent资产 | 规划193、首阶段46，状态混合 | 可归并的技能、提示词、知识、工具和评估资产 | 实际可用率、重复度、权限、质量、成本和所有者 |

## 先建立工具能力登记册

每个可供Agent使用的能力要登记为一个可审计对象，而不是一段提示词或一个系统名字：

| 必填字段 | 说明 |
| --- | --- |
| 系统与能力ID | 稳定名称、版本、环境和来源系统 |
| 业务对象与范围 | 品牌、市场、账号、商品、客户/供应商对象和时间范围 |
| 主数据与数据分类 | 权威来源、刷新、敏感等级和最小访问集 |
| 访问身份 | 服务身份或受控运行身份；不在提示词、仓库或会话中保存密钥 |
| 操作类型 | 读取、校验、写入、外部发起、回执查询、补偿或冻结 |
| 输入/输出契约 | 经目标系统核实的schema、错误码、时限和限流 |
| 动作策略 | 适用角色、场景、参数、对象、预算/约束、有效期和幂等要求 |
| 回执与恢复 | 可查询的外部状态、补偿方法、超时和部分成功处理 |
| 评估状态 | 文档可见、已连接、离线回放、影子运行、有限实操或持续经营 |

没有这份登记册，不把“系统已上线”或“已有Agent”写成可被自主调用的能力。

## 推荐接入顺序

| 阶段 | 首要对象 | 目的 | 产出 | 进入下一阶段的证据 |
| --- | --- | --- | --- | --- |
| 0 | 全部候选系统 | 建立工具能力登记册、对象映射和访问边界 | 可核实的连接清单 | 每项明确系统状态、负责人、环境和读写能力 |
| 1 | Shopify | 验证首个DTC样本的Shop、订单/销售调整、商品价格、渠道库存、流量和结算候选事实 | Shopify数据契约、只读工具、质量状态 | Shop/SKU范围唯一，指标可重算，PII被最小化，越界在请求前被拒绝 |
| 2 | 实际广告平台、自研ERP、PLM、QMS、WMS、TMS | 补齐投放成本、商品、供应、库存、质量和履约的权威记录与回执 | 跨源覆盖矩阵、system-of-record映射、回执查询 | 同一对象可对账，缺失域显式冻结，重复事件不重复执行 |
| 3 | RootData、Amazon Seller Central、数智星图、CRM、KOL与内容系统 | 扩展Amazon、客户、内容和外发等后续场景 | 渠道数据契约、动作策略与工具UI | 各渠道事实独立，客户数据和外发范围受控 |
| 4 | 经验证的写入能力 | 仅把已定义的动作纳入Agent自主闭环 | 动作策略、幂等、回执、补偿和自治异常账 | 通过离线、影子和有限范围验证 |

这是D-033至D-049后的执行顺序；首个Shopify入口采用试点专用Dev Dashboard App和[只读连接器登记契约](SHOPIFY-READONLY-CONNECTOR-REGISTRATION.md)，同一Shopify Organization下认证固定为`client_credentials`；`custom.product_family=wearable_breast_pump`定义产品家族成员，一次性负责人确认的Product GID清单负责初始化，首批SKU以官方`Total sales by product variant` CSV中的原始Top 5经三类风险剔除后形成[范围清单](../../08-data/BVS-01-SHOPIFY-SKU-SCOPE-MANIFEST.md)。目标Shop先以只读预检证据包验证身份/Scopes、Level 1资格、订单字段与45天保留控制、Definition三态、目录、种子和报告能力，任何写入另案。D-049进一步固定直接在目标Dev Dashboard读取[9项资格证据](SHOPIFY-LEVEL1-QUALIFICATION-EVIDENCE-PACK.md)，不以development store替代目标App/Shop/Organization关系；按App类型适用官方Level 1矩阵，并对身份、组织关系、PCD状态、Data protection要求、Scopes、用户权限和分发状态分别留证。声明Scope已固定为Products、Orders、Inventory、Locations和Markets五项读取；订单采用Level 1最小必要字段、原始响应零持久化、规范化行45天加密保留、模型仅见SKU日聚合。资格证据当前仍为`NOT_OBSERVED`，浏览器连接验证尚未完成；删除/访问/备份TTL测试、实际授权、Shop/App/SKU标识及真实实例仍由R04-Q5实例化。Scope、PCD Shape、保留控制、成员或报告能力不匹配时HOLD。本决定不隐含已创建定义、回填字段、读取客户/报表/商品、修改商品、创建App、交换Token、调用API或获得生产写入授权。

2026-09-16决定更新：当前没有可执行的Amazon SP-API、RootData或数智星图只读入口，D-033确认Shopify DTC先行。D-050进一步确认Shopify是无上线产品的空白新店；D-051要求当前只完成店铺治理底座方案，不实例化连接器或Case。未来连接器实例、Level 1、订单数据和30天报表分别延期到`SHOP-G6/SHOP-G7`；D-033至D-049仍是目标合同。Shopify只负责自身渠道事实，不完成Amazon US订单、广告、价格与FBA库存验证；Amazon入口可用后另建渠道Case和连接器证据包。

## DeepSeek Harness的连接方式

| 方式 | 适用对象 | 已核实方向 | 需要目标环境验证 |
| --- | --- | --- | --- |
| native tool | 已有内部服务或轻量包装器 | dsh-tools可注册typed tool并按Agent scope限制 | 目标插件、权限、服务端政策和审计链 |
| MCP | 有MCP server的内部或外部服务 | dsh-mcp-client支持stdio或Streamable HTTP，将工具命名为mcp__server__tool | 企业网络、认证、超时、工具发现与schema |
| API adapter | 没有MCP但有正式API的系统 | 可由受控适配器包装为工具 | OAuth/服务身份、字段、限流、幂等和回执 |
| hook / event | 状态变化、回执和告警 | 可作为工单信号或工具后的事件 | 事件顺序、重复、签名、重放和失败恢复 |
| tool UI/UX | 工单、动作、回执和异常的工作卡 | 本机工具文档说明展示意图与toolview机制 | 企业Host是否消费、数据脱敏和访问控制 |

本机文档显示MCP桥接的是tools，不能假定资源或prompts同样可用；服务器连接、超时和重连也会影响实际运行。详细证据见[EVD-020](../../14-research/SOURCES.md)和[能力矩阵](CAPABILITY-MATRIX.md)。

## 版本事实必须先对齐

本机安装包为LUTE Agentic System Desktop 2.0.5，内含Harness 0.1.2-rc.1；本机 `/opt/homebrew/bin/dsh` CLI 自报 0.1.5-rc.1；企业材料则描述一个仍在建设中的、以DeepSeek Harness为基础的平台并提到2.0.4。三者不是可以互相替代的版本证明。

在导出或编写任何preset、MCP配置、plugin配置或导入包前，必须从目标环境确认：产品身份、Harness/插件版本、实际profile、配置schema、tool presenter、身份/密钥托管和审计位置。本项目不生成貌似可运行的猜测配置。
