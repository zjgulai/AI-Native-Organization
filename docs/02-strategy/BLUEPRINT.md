# Momcozy 50岗位Agent自主经营总体方案

采用50种逻辑AI岗位、每张Case一个上下文所有者、按阶段加载Skills、工具连接业务系统、业务控制层记录策略与回执的组织方式。GMV为第一优先级，同时把取消退款、现金、客户体验、产品质量和经营损失作为单独可见的约束。

战略框架v1.1保留业务责任基线，D-020至D-026已将运行架构升级为50个Role Profiles、单Case Agent、不可变Bundle、八阶段产物门禁协议、一张Case只绑定一条主价值流和一个主场景，以及FLOW-07模型外确定性紧急保护。初始运行不设置真人负责人或HITL为常规节点。具体系统连接、动作策略、Guard规则、服务身份、经营对象和生产动作仍未配置或授权。

## 经营问题与第一性原理

经营规模约100亿人民币，1013家活跃店铺、2000+SKU，Amazon占比65%、独立站15%；业务集中于Momcozy与可穿戴式吸奶器。产品模式为OEM，同时组织材料列有工程、软件、用户研究与产品研发能力。上述经营数据为企业负责人陈述，组织依据及人数差异见[现状评估](../01-discovery/ORGANIZATION-ASSESSMENT.md)。

当前系统的核心瓶颈不是缺少报表或助手，而是经营信号、职责、工具、数据和动作结果之间断裂：数据治理混乱，业务需求排队，1000+店铺和2000+SKU使局部动作很容易彼此冲突，且增长过度依赖单一爆品。

第一性原理是把组织变成一个可验证的经营控制循环：

1. 每个信号先进入带业务范围的场景工单，而不是流入部门群聊。
2. 模型外Case Control为Case确定唯一主价值流、唯一主场景、业务范围和主岗位，只把当前阶段必要的Skill描述、工具和数据引用装配进上下文。
3. 每个工单只有一位AI结果负责人和一个主岗位人格；专业能力通过Skills与阶段产物贡献，独立复核通过Assurance Contract与外部门禁生效。
4. 工具是Agent的手和脚；提示词不是权限，工具UI不是权威记录。
5. 业务控制层或受控目标系统校验策略、范围、参数、幂等、回执和恢复；无策略或回执不明时冻结受影响范围。
6. 效率用GMV、经营约束、等待、异常、全成本和复用能力衡量，不用聊天量或Agent数量衡量。
7. FLOW-07只有在已发布确定性规则完整命中且唯一Case绑定成立时才可先行降低暴露；绑定前歧义只冻结信号范围而不创建残缺Case，Emergency Guard不由模型控制，紧急Attempt不替代STG-07，恢复和扩大性动作仍运行完整八阶段。

## GMV目标与两条增长主线

**存量经营主线**围绕吸奶器及已销售商品，把库存、广告、价格、内容、渠道和复购放进同一行动包。Amazon为第一候选样本，独立站和其他渠道共用岗位但按账号、市场和规则隔离。

**新品验证主线**从用户使用问题出发，贯通研究、产品、工程、OEM、质量、品牌和市场验证。每个机会必须有商业假设、可观察的成功与停止条件，之后再调用受控资源和外部执行。

原始GMV、取消退款、贡献、现金和客户质量分别展示。100亿对应的统计口径、年度、权威来源和数值阈值由首个样本的数据契约确认；当前不将100亿自动当作已审计GMV。市场归因报表、整体增长和实验增量分开，避免多个岗位重复认领同一笔GMV。

## 人格、灵魂与可检验行为

人格不是角色包装。每个分身都把表达方式、证据偏好、冲突取舍和停止行为写成可测试的规则。例如：

- AGT-021北辰必须把广告、库存和价格放入共同经营方案。
- AGT-008拓新在证据不支持时提出停止，不用概念数量证明创新。
- AGT-045同尺不能把不同口径拼成结论。
- AGT-005守衡不能让发起者验收自己的动作。
- AGT-002枢衡不能用催促代替责任、接收条件和异常状态。

人格可影响分析和协作，不扩大预算、账号、产品事实、数据访问或工具范围。岗位卡中每项原则都有诱导情境，检验是否提出异议、保留证据、正确分派、复核或冻结范围。

## 日常经营如何协同

场景工单从业务信号开始，逐步绑定品牌、市场、账号、商品集合、时间窗、主岗位、Bundle、数据来源和策略版本。Case Control装配唯一主岗位人格与必要Skills；同一个Case Agent依次完成证据诊断、方案产物和Action Intent。Assurance Gate、Policy Gate与Execution Broker分别控制产物接收、动作许可与实际执行。

1013家店铺不需要1013套永久岗位；2000+SKU也不能直接与店铺数相乘。系统以真实变化、经营节奏、事件和例外触发任务，并按账号、产品和库存/预算对象隔离并发工作。

无适用策略、越过范围、回执不明、数据冲突或外部主体未响应时，不停止整家公司，也不重跑整单。只冻结受影响对象，写入自治异常账，查询外部状态后再重试、补偿、返工或恢复。这条候选基线等待R04-Q3确认。

[自主运行模型](../07-orchestration/AUTONOMOUS-OPERATING-MODEL.md)和[协同图谱](../07-orchestration/COLLABORATION-GRAPH.md)说明八阶段、Stage Artifact、接收门禁、冲突和恢复。

## 数字化中心的职责重构

数字化中心不再充当被动IT需求队列，应成为50个Agent可复用的数据产品、工具、动作策略和运行可靠性供给方。

以GMV为例：AGT-045维护指标与对象关系，AGT-046提供带质量状态的数据产物，AGT-047把真实系统能力包装为受控工具，AGT-049记录运行与恢复，AGT-050约束身份和权限。AGT-003、021、026、032和041在同一场景内消费这些能力，形成可核对的经营行动包。

工作优先级按经营价值、时效、复用、数据质量和实际代价排序。任何系统已上线、Agent已存在或UI已显示，都不等于已形成可自主调用的工具能力；必须进入[工具能力登记册](../10-platform/deepseek-harness/SYSTEM-INTEGRATION-INVENTORY.md)。

## DeepSeek Harness与业务系统

DeepSeek Harness承担Case Agent会话、Skills和受限工具调用；业务控制层承担Case Control、阶段状态、策略、幂等、外部回执、异常账与恢复。窄范围只读Delegate只作为可独立验收的工具调用，不形成LLM多Agent路由。

本机资料已显示native tools的scope限制和单调guard、MCP tools桥接、工具调用展示意图等能力方向。企业材料同时表明品牌AI平台仍在建设，RootData、ERP、PLM、QMS、WMS、TMS、Amazon、Shopify和CRM是候选系统资产。目标环境版本、插件、接口与身份尚未核实，具体方法见[Harness落实方案](../10-platform/deepseek-harness/IMPLEMENTATION-PLAN.md)和[系统接入盘点](../10-platform/deepseek-harness/SYSTEM-INTEGRATION-INVENTORY.md)。

## 实施顺序与验收

| 范围 | 应产生的实物交付 | 扩展依据 |
| --- | --- | --- |
| 框架决策 | 50岗位、场景职责、八阶段协同、五契约、动作策略原则、工具资产盘点 | 关键经营取舍确认 |
| 经营样本 | 一个明确范围的FLOW-01与FLOW-06；FLOW-02先做验证设计 | 有同口径基线、真实输入和可核对数据 |
| 受控运行 | 读取工具、工单、策略、回执、异常账与工具UI | 跨范围拒绝正确、外部效果可核对、冻结可恢复 |
| 有限闭环 | 明确对象范围内的策略允许动作 | GMV、约束、服务与全成本达到约定标准 |
| 组织扩展 | 向其他产品/渠道扩展，必要时再设计HITL和真人组织 | 复用有效、峰值和异常可承受 |

没有预设固定周数、节省人数或收益率。当前重点是用少量真实对象证明自治闭环，再扩展到更多店铺、SKU和渠道。

## 经济性与未来组织

初始运行不以人员缩编作为前置。全成本包括模型、软件、数据、集成、工具调用、运行维护、外部执行、异常和事故；未来如引入HITL或组织调整，再单列实际人工劳动、专业签署和值班成本。

[容量和成本模型](CAPACITY-AND-COST.md)保留三本账和取数方法。任何人员变化结论都必须来自真实经营结果、自治异常、外部执行、全成本和未来组织决定，而不是从“50个岗位”倒推。
