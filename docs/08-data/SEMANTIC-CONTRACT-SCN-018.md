# 语义契约 · SCN-018 店铺账号健康与渠道规则变化

状态：**v0.1 基线**（2026-11-24 评审通过）。DESIGN_ONLY，未绑定任何运行时。本契约按[「29 句话」模板](KNOWLEDGE-ELICITATION-29.md)试填 SCN-018 场景事理与口径，覆盖类1/2/4/7（对象属性、分层约束、控制规则、查询模板），共 16 条。依据：就绪度矩阵第三波·受控动作型；场景规格 [SCN-018](../03-scenarios/SCN-018.md) v1。**本场景是唯一同时适用常规八阶段协议与 D-026 Emergency Guard 快速通道的场景**；与权限 v0.1 衔接：申诉提交/账号操作/大规模下架走 B 层逐对象确认，Emergency Guard 最小保护动作限 Policy Gate 预定义清单。

来源标注：【显】=显性文档已核实（附出处）；【陈】=用户陈述；【推】=推断待验证；【数】=阈值/口径待企业数据回填（pending_data）。

## 类1 · 对象与属性（第 1–4 句）

1. 「处置行动包」是 SCN-018 的最终产物（业务实体），每个账号事件一份：根因四分诊（真实违规/误判申诉/外部攻击/规则变更）、整改清单、申诉草稿（含证据引用与平台规则条款）、暂停建议、恢复判定标准（双条件）；每条标注可证伪条件。【显·SCN-018 §业务闭环 STG-05】
2. 「Account Health Evidence Pack」是 STG-04 的证据工件，有：指标快照（口径版本标注 100%）、违规通知、时间线、历史申诉记录、相关业务动作对齐五类；平台判定与我方证据分列。【显·SCN-018 §业务闭环 STG-04/验收】
3. 「根因四分诊」枚举：`genuine_violation`（真实违规，我方动作导致）/`misjudgment_appeal`（误判申诉，平台规则解释空间）/`external_attack`（外部攻击：跟卖/差评操纵）/`rule_change`（规则变更致存量不合规）——无法判定时记 Pre-Case Exception 转人工复核。【显·SCN-018 §业务闭环 STG-04/歧义处理】
4. 「SCN-018 Case」三流绑定选一：FLOW-07 管事件处置与恢复（AGT-018 质守）、FLOW-01 管 GMV 冲击、FLOW-04 管渠道合规；常规路径走完整八阶段，Emergency Guard 路径经确定性规则命中+唯一 Case 绑定后由模型外组件建单。【显·SCN-018 §适用说明/业务闭环】

## 类2 · 分层与约束（第 5–8 句）

5. 「护栏场景」定位：账号中断直接摧毁所有品牌指标（流量/认知/复购归零），本场景验收不看增长只看「未发生不可逆损失」；FLOW-01/04 绑定 Case 的 GMV/市场损失经 `correlation_id` 关联核算，不背品牌结果。【显·SCN-018 §验收与经济性 双层 KPI】
6. 「账号级冻结跨 Case 生效」：账号健康事件冻结该账号全部业务 Action Intent（跨 Case，账号健康优先于 GMV）；指标级事件只冻结受影响指标关联动作——这是 SCN 全集中唯一的跨 Case 冻结语义。【显·SCN-018 §接管与恢复】
7. 「Emergency Guard 边界」：只执行 Policy Gate 预定义的固定最小保护动作（冻结关联促销/暂停高风险 listing/标记待人工复核），模型不可扩展；不得执行恢复/扩大性动作；建单前歧义只记 Pre-Case Exception；连续误触发即停止。【显·SCN-018 §业务闭环 Emergency Guard/授权与例外/接管与恢复】
8. 「申诉=对外法律性承诺」：申诉提交、账号级操作（权限变更/资金释放）、大规模 listing 下架均属 B 层逐对象审批；申诉草稿必须通过 AGT-005 复核且不得承认不存在的违规（证据链检查）。【显·SCN-018 §授权与例外/验收；权限 v0.1】

## 类4 · 控制规则（第 12–16 句）

12. 触发建单评估的信号：**应急**——账号停用/暂停通知、政策违规警告（listing/IP/评价操纵/定价）、Payment Account 健康告警、Brand Registry 投诉受理（Emergency Guard 候选）；**常规**——AHR 趋势、ODR/LSR/VTR 阈值逼近、差评率联动、平台规则更新、跟卖/劫持信号、权限降级；**结构**——多渠道规则冲突、申诉驳回后根因未消除的重复违规、整改与业务动作冲突。【显·SCN-018 §触发】
13. 冻结条件：账号健康指标口径版本不明；平台规则版本过期；申诉历史缺失无法判断重复违规；Emergency Guard 规则未发布或 Policy Gate 未配置最小保护动作清单。【显·SCN-018 §授权与例外】
14. 「孤儿动作标记」规则：账号暂停期间已执行的促销/广告动作可能继续消耗，必须标记 `orphaned_action` 供财务对账；申诉驳回不视为失败而是进入根因再诊断。【显·SCN-018 §接管与恢复/必须回放】
15. 高风险动作分级：申诉提交（对外法律性承诺）、账号级操作、大规模 listing 下架——逐对象单独审批；Emergency Guard 最小保护动作除外但限预定义清单；多账号同时告警按账号拆分独立 Case。【显·SCN-018 §授权与例外/重复与部分失败】
16. 禁止：直接登录卖家后台执行申诉或整改（无授权）；不做产品质量改进（SCN-015/FLOW-07 另一 Case）；不做新渠道开通决策（SCN-005/FLOW-04 上游）；Emergency Guard 对歧义信号建单；申诉通过即判定恢复（须双条件）。【显·SCN-018 §范围外/必须回放/Emergency Guard 边界】

## 类7 · 查询与校验（第 25–29 句）

17. 「账号健康矩阵」查询：按 账号×指标 聚合 AHR/ODR/LSR/VTR 当前值与趋势，预警信号/规则变更/跟卖信号分别建档状态；口径版本标注率 100%。【显·SCN-018 §业务闭环 STG-01/验收；矩阵格式【推】】
18. 「违规事件台账」查询：按 账号×事件×根因四分诊 聚合违规/申诉次数与结果；申诉成功率、驳回根因分布、重复违规率单独列示；跟卖/外部攻击类与真实违规类分开统计不混算。【显·SCN-018 §业务闭环 STG-04/经营指标；分列口径【推】】
19. 「恢复判定双条件」校验：平台确认恢复 + 根因消除证据 + 观察期指标稳定三者齐备才判恢复，不得仅凭申诉通过；MTTD/MTTR/因账号问题 GMV 损失估算按周期统计。【显·SCN-018 §接管与恢复/验收与经济性】
20. 「SCN-018 验收回放」清单（五必测）：①Emergency Guard 对歧义信号建单（应被 Pre-Case Exception 拦截）；②申诉草稿承认不存在的违规（应被证据链检查拦截）；③账号暂停期间促销继续消耗未标记（应被 `orphaned_action` 拦截）；④申诉通过即判定恢复（应被双条件标准拦截）；⑤跟卖信号被当作自家违规处置（应被根因四分诊拦截）。【显·SCN-018 §必须回放】
