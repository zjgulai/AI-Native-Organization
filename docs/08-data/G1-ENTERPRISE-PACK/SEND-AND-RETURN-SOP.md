# G1 交付包 · 发送与回传 SOP

状态：**v0.1**（2026-11-26 建立）。配合 `G1-ENTERPRISE-PACK` v0.1 基线使用。本文档只覆盖「怎么发出去、收回来怎么处理」；包内容与验收口径以包内文件与 `../G1-DATA-REQUIREMENTS.md` 为准。

> **仓库可见性警告**：`zjgulai/AI-Native-Organization` 为 **PUBLIC** 仓库。任何企业回传数据（含脱敏快照、字段字典、截图、规则集原文）**一律不得提交本仓或任何公开位置**；公开仓只允许写状态结论与计数。

## 1. 发送前检查

- [ ] 包版本为 v0.1 基线（`README.md` 头部状态行）
- [ ] zip 重新生成（§3 命令），确认打包日期为当日
- [ ] 接收人覆盖两类：**数据/运营/IT 接口人**（填 G1P-02/04/05）+ **经营层/品牌/合规负责人**（填 G1P-03，纯书面无技术依赖，可先启动）
- [ ] 渠道走企业微信/邮件；zip 不含账号密码与客户数据，但仍按企业资料对待，不发公开群

## 2. 发送说明（复制即用）

> 附件是「G1 数据就绪交付包」v0.1，请按以下顺序使用：
>
> 1. 先读 `README.md`——里面有三层交付物（G1A 自有渠道 / G1B 平台第三方 / G1C 客户规则集）和已确认信息预填说明，**已确认的不用重复填**；
> 2. 数据/运营/IT 接口人填 `G1P-02`（可得性确认）+ 按 `G1P-04` 导出指引取数 + 按 `G1P-05` 模板打包首份证据；
> 3. 经营层/品牌/合规负责人填 `G1P-03`（10 项阈值规则，书面确认即可，无需等数据）；
> 4. 回传方式：直接在表内「回填」列填写后回传文件，或按 05 模板逐源打包；
> 5. 边界：不需要提供任何系统账号密码/API Token/客户个人信息明细；数据以脱敏导出快照交付。
>
> 有疑问直接回复本消息，按源逐项对齐。

## 3. 打包命令

```bash
cd docs/08-data/G1-ENTERPRISE-PACK
zip -r -X "export/G1-ENTERPRISE-PACK-v0.1-$(date +%Y%m%d).zip" \
  README.md G1P-0*.md
```

`export/` 与 `returns/` 已被本目录 `.gitignore` 排除——zip 和回传件永不入库。

## 4. 回传接收流程

| 步骤 | 动作 | 产出 |
|---|---|---|
| 4.1 登记 | 收到回填件 24h 内在 `docs/00-project/STATUS.md` 记一行：收讫日期 / 来源 / 覆盖范围（哪些表哪些源） | STATUS 条目 |
| 4.2 私有存放 | 回传件放入 `returns/`（本地私有目录）；**原始文件永不进 git** | `returns/` 本地副本 |
| 4.3 PII 核查 | 按 G1P-05 六要件核对；发现未脱敏 PII（买家邮箱/电话/订单号明细等）**立即退回企业侧重导**，不进入任何处理 | 核查结论（可入库的一句话） |
| 4.4 分流回填 | ① 02/03 表「回填」列 → 对照 `../G1-DATA-REQUIREMENTS.md` 状态列回填内部规格；② 05 证据包 → 逐源登记 snapshot_hash/时间窗/缺口清单；③ 缺口 → 记入缺口台账并反馈补件 | 内部规格状态更新 |
| 4.5 公开仓口径 | 公开仓只写：「G1A Shopify 样例已收讫」「G1C 规则集 N/10 项已确认」这类结论与计数；字段字典、报表截图、规则原文不入库 | STATUS/契约评审记录 |

## 5. 验收门禁衔接

- 三层各自验收：**G1A** 自有渠道事实、**G1B** 平台与第三方事实、**G1C** 客户规则集（无需数据样例，书面即回填权限层【数】位）。
- 全部就绪 → PILOT-G1 分源验收 → FLOW-09 阶段门 **G1 复核**（当前 G1 判定为「未就绪」，本流程是其解锁路径）。
- 回填闭环规则（引 `../G1-DATA-REQUIREMENTS.md`）：每解锁一项 pending_data，在对应契约「评审记录」标注数据来源与日期；全部回填后产出 SCN-002 事理规则显性化 v0。

## 6. 例外与升级

- 企业侧某源**不可得**：02 表标「不可得」+ 书面替代方案，进缺口台账，不阻塞其他源验收。
- **两轮补件仍缺**同一关键源：升级为方案级决策（是否缩小试点品类/渠道范围），记入 DECISIONS。
- 回传内容与包预填信息（F-041~F-049）冲突：以企业回传为准修订包内「已确认」列，并在 STATUS 注明冲突项。
