# G1 回传 → 数据需求回填映射（BACKFILL-MAP）

版本：v0.1（2026-11-26 建立）。本文是 `SEND-AND-RETURN-SOP.md` §4.4「分流回填」的执行映射：把企业回传三件套（G1P-02 可得性表 / G1P-03 规则集 / G1P-05 证据包）逐项对到 `../G1-DATA-REQUIREMENTS.md` 的章节锚点，规定每类回传状态的回填动作。

**边界**：本文不含任何企业数据。回传原文、INTAKE-REPORT、缺口台账明细一律留 `returns/` 私有区；公开仓只落状态结论与计数（SOP §4.5/§6 警告）。覆盖度由 `scripts/intake-g1-returns.py` 启发式产出，「部分覆盖」必须人工复核上下文后才可回填。

## 1. 输入与输出

| 输入 | 载体 | 覆盖对象 |
|---|---|---|
| G1P-02 可得性表 | INTAKE-REPORT 覆盖度 + 逐项明细 | 77 个核实项：Part0 系统盘点 11 + PartA 五源盘点 30 + PartB 出海新源 36 |
| G1P-03 规则集 | INTAKE-REPORT 覆盖度 | R1~R10（与 `G1-DATA-REQUIREMENTS.md` §4 规则 1~10 一一对应） |
| G1P-05 证据包 | INTAKE-REPORT 六要件/元数据/PII 章节 | 逐源证据包（FLOW-09 五源走完整六要件；出海新源走 6' 宽松版） |

输出落点：

- `../G1-DATA-REQUIREMENTS.md` §1/§2 各行「状态」与「企业侧待办」确认结果；
- 同文件 §3 `pending_data` 映射表逐项解锁标注（§5 回填闭环规则）；
- 同文件 §4 规则表状态列 + `SEMANTIC-PERMISSION-V01` 等契约【数】位；
- 缺口台账（私有，`returns/`）+ 按优先级反馈补件（SOP 4.4③）。

## 2. 状态 → 回填动作

| INTAKE 状态 | 含义 | 回填动作 |
|---|---|---|
| 已覆盖 | 结构化表单整行作答，或分隔表格答案列填满 | 可得性结论登记到对应 §1/§2 行；字段字典、快照哈希仍以 G1P-05 证据包为准复核 |
| 部分覆盖 | ID 行提及 / 关键词命中 / 证据包行号引用 | 人工复核命中上下文：确属相关则补齐缺项字段；确无关则在缺口台账记「复核后不适用」 |
| 缺失 | 无任何结构化或文本信号 | 按 §3 优先级催补；P0 项进缺口台账并反馈企业侧；确实不可得的写明原因与降级影响（G1P-05 要件⑤口径） |

PII 命中项（报告 PII 章节）一律按 SOP 4.3 退回重导，不进入回填。BINARY/解析失败文件人工分流，不计入覆盖度分母的结论需在台账注明。

## 7. 收讫后操作步骤

1. 跑 `python3 scripts/intake-g1-returns.py` 生成 `returns/INTAKE-REPORT-<date>.md`（私有区）；
2. 按 §2 逐项复核「部分覆盖」，在缺口台账落定结论；
3. G1P-03 逐项确认 → §4 表标状态 + 评审记录日期；
4. G1P-05 逐源核对六要件 → §1/§2 状态列 + §3 pending_data 解锁标注；
5. 缺口按优先级反馈企业补件（SOP 4.4③）；P0 缺口未补前对应源保持未验收；
6. 公开仓只记 `docs/00-project/STATUS.md` 一行收讫/验收结论与计数（SOP 4.5），字段字典、报表原文、规则原文不入库。
