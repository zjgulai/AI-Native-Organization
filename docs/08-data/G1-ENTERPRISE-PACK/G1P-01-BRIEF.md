# G1P-01 交付说明

版本：v0.1 基线（2026-11-25 评审通过）。本文说明本次数据交付的背景、范围、边界与推进顺序；具体填写见 `G1P-02`~`G1P-05`。

## 1. 背景：我们为什么需要这些数据

本项目为跨境电商 AI 组织变革方案：约 50 个 AI 数字岗位、8 条价值流、20 个业务场景。方案要从「设计图」走到「可运行」，第一道门槛是**数据基线**——诊断、预测、对账、客户分层等场景全部依赖真实经营数据，缺数据的指标只能标记「未知」，不能推断填充。

当前两条试点线都卡在同一个前置条件上：

- **FLOW-09 品牌资产诊断**（Amazon vs DTC 覆盖缺口）：四源数据契约与读取范围已设计完成，缺企业侧逐源确认与首份导出样例；
- **出海产品层**（117 项运营工作）：需要五源之外的八组新数据（结算财务、广告、VOC、合规、履约库存、店铺健康、达人分层、多平台价格），尚未盘点可得性。

## 2. 我们需要三层交付物

| 层 | 内容 | 对应表单 | 通过条件 |
|---|---|---|---|
| **G1A 自有渠道事实** | Shopify DTC 分析 + 社媒公开数据 + DME/保险渠道聚合 | `G1P-02` Part A | 范围包逐源书面确认 + 首份脱敏导出样例 + 字段字典核对通过 |
| **G1B 平台与第三方事实** | Amazon 报表 + 竞品监控工具 + 出海层 P0 数据源 | `G1P-02` Part B | 同上；缺 G1B 时诊断仍可产出但 Amazon 侧证据降级 |
| **G1C 客户规则集** | 10 项阈值/规则（预算幅度、触达批量、价格底线、退款上限等） | `G1P-03` | 书面规则集到位即回填，**不需要数据样例** |

三层相互独立、可并行。G1A/G1B 各通过至少一源后，FLOW-09 首个诊断 Case 即可进入影子运行；出海层数据源按优先级分批接入，不阻塞试点。

## 3. 边界声明：我们不需要什么

- **不需要任何凭据**：不索取后台账号密码、API Token、OAuth 授权；首期全部走「人工导出/快照」路径。
- **不需要个人信息明细**：客户/买家级字段（邮箱、姓名、订单号、地址、handle）一律不进分析层；导出环节即排除，只要聚合计数。
- **不需要写入权限**：本次交付纯只读；任何对外动作（改价、发券、回评、退款执行）仍走逐次人工确认，与本次数据采集无关。
- **数据不出企业侧原件**：原始导出文件存企业侧受控位置；我方只接收脱敏样例、字段字典与快照哈希，哈希可复算验证完整性。

## 4. 数据如何被使用

- 每源一份**脱敏样例 + 字段字典**用于核对口径；确认后按约定粒度/时窗定期提供快照。
- 缺数据记 `data_gap` 并标注降级路径，**不推断、不补零、不拿第三方估算冒充官方值**。
- 跨源同指标不一致时记录口径差异分列展示，不取平均消除冲突。
- Amazon 品牌分析类报表天然为**周粒度、滞后 2–3 周**，分析按此口径设计。
- 竞品/社媒指标绑定版本化口径（竞品集合 v1 已确认），计算可回放。

## 6. 建议推进顺序

1. **本周可启动**：`G1P-03` 规则集（纯书面确认，无技术依赖）+ Shopify 首份报表样例（最高频数据源）。
2. **G1A 批次**：Shopify 五数据集 + 社媒账号清单 + DME 产品线导出方式确认。
3. **G1B 批次**：Amazon 四报表样例 + 竞品工具字段盘点。
4. **出海层 P0 批次**：结算财务 + VOC 评价 + 合规资质台账 + 店铺账号健康——这四组解锁对账、客服、准入、账号风控等高频工作。
5. **出海层 P1/P2**：广告、履约库存、达人分层、多平台价格——按实际开通范围裁剪，**不必一次全量**。

## 7. 提交与验收

- `G1P-02`/`G1P-03` 直接回填后回传；首份数据样例按 `G1P-05` 模板逐源打包。
- 每源通过「可得性确认 + 六要件证据包 + 字段字典核对」后，该源进入分层验收（G1A/G1B）。
- 全部 `pending_data` 项随数据基线逐项回填；回填完成后我方产出事理规则显性化版本。
