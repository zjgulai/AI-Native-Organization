# 语义契约 · SCN-014 订单、交付与渠道异常

状态：**v0.1 基线**（2026-11-24 评审通过）。DESIGN_ONLY，未绑定任何运行时。本契约按[「29 句话」模板](KNOWLEDGE-ELICITATION-29.md)试填 SCN-014 场景事理与口径，覆盖类1/2/4/7（对象属性、分层约束、控制规则、查询模板），共 16 条。依据：就绪度矩阵第三波·受控动作型；场景规格 [SCN-014](../03-scenarios/SCN-014.md) v1。与权限 v0.1 衔接：STG-07 全部 Action Intent 走 B 层客户确认（PV-11~20），当前阶段无授权连接时全部 `NoActionRecord`。

来源标注：【显】=显性文档已核实（附出处）；【陈】=用户陈述；【推】=推断待验证；【数】=阈值/口径待企业数据回填（pending_data）。

## 类1 · 对象与属性（第 1–4 句）

1. 「异常处置包」是 SCN-014 的最终产物（业务实体），每个异常一条：环节定位（下单→支付→仓储→承运→清关→末端→渠道同步七环节之一）、根因分类（六类枚举）、处置建议、客户沟通要点、根因反馈建议、可证伪条件；反馈建议必须标注接收方 Case/流程。【显·SCN-014 §业务闭环 STG-05】
2. 「Exception Evidence Pack」是 STG-04 的证据工件，有：异常清单、承运商轨迹节点、渠道状态快照、关联工单摘要、时间线五类；验收判据为轨迹/快照证据覆盖率 100%，环节定位必须引用具体证据。【显·SCN-014 §业务闭环 STG-04/验收】
3. 「根因六分类」枚举：`system_sync_fault`（系统同步故障）/`warehouse_error`（仓储操作失误）/`carrier_customs_delay`（承运商/清关延误）/`channel_rule_change`（渠道规则变更）/`supplier_stockout`（供应商缺货）/`process_defect`（我方流程缺陷）——每个异常必须选一类并给依据。【显·SCN-014 §业务闭环 STG-04/验收】
4. 「SCN-014 Case」四流绑定选一主流：FLOW-03 为主（交付职权），FLOW-04/05/07 按异常性质选一不兼负；升级为账号健康事件时转 SCN-018 的 FLOW-07 Case，经 `correlation_id` 关联不在本 Case 背负。【显·SCN-014 §适用说明/业务闭环 STG-02】

## 类2 · 分层与约束（第 5–8 句）

5. 「异常收敛器」定位：本场景产出不是「处理掉异常」而是「定位环节+根因反馈回上游」——处置建议、客户沟通（移交 SCN-015）、根因反馈（移交 FLOW-03 计划/SCN-015 话术/FLOW-04 渠道配置）、预防措施四路分流，结果责任不越界。【显·SCN-014 §适用说明/经营目的】
6. 「定位完备性优先于处理速度」：异常无法定位到环节时记 `unresolved_location` 并扩大证据而非猜测归因；多渠道同现异常优先假设外部共同原因（物流商/供应商）而非分别归因。【显·SCN-014 §当前基线/歧义处理】
7. 「客户信号只引用不导出」：SCN-015 关联工单只引用已验收摘要，PII 不进入 Evidence Pack；渠道 API 故障期间状态标 `source_unavailable` 不作我方缺货结论。【显·SCN-014 §输入/业务闭环 STG-01】
8. 「处置权限上限声明」：Case Charter 固定主流、范围（渠道/SKU/异常类型/时间窗）与处置权限上限；重发/退款/渠道工单/listing 修复/库存重映射全部以逐对象 Action Intent 存在，当前无授权连接时记 `NoActionRecord`。【显·SCN-014 §业务闭环 STG-02/07；权限 v0.1 PV-11~20】

## 类4 · 控制规则（第 12–16 句）

12. 触发建单评估的信号：每日异常扫描、周度异常复盘、大促小时级监测；订单状态超时未流转、承运商轨迹停滞、清关延误告警、库存同步偏差、Listing 抑制、跟卖信号、渠道 API 错误率上升、退货率/缺货率异常联动；同环节聚集标 `systemic_candidate`、跨渠道同现优先外部原因。【显·SCN-014 §触发】
13. 冻结条件：订单/物流数据源不可用且无法交叉验证；渠道 API 故障期间无法确认真实状态；异常量超 Case 容量且未分级；疑似账号健康事件但 SCN-018 Case 未建立。【显·SCN-014 §授权与例外】
14. 「残留异常防重复处置」规则：处置后异常仍存在记 `residual_anomaly` 进入再诊断，不得对同一异常重复处置；根因反馈未被上游接收的保持 `feedback_pending` 直至确认，不得关闭 Case。【显·SCN-014 §接管与恢复/必须回放】
15. 高风险动作分级：批量重发/退款、渠道官方工单升级、listing 大规模修改、清关申报变更——逐对象单独审批（对齐 B 层高风险子集）；跨渠道异常率统计禁止直接平均（按渠道分列后归因）。【显·SCN-014 §授权与例外/必须回放；权限 v0.1】
16. 禁止：直接操作 ERP/WMS/渠道后台（无授权）；不做客服话术（SCN-015 关联 Case）；不做账号健康治理（SCN-018）；不做正常补货采购决策（SCN-006/007）；把渠道 API 故障误判为我方缺货；多渠道异常率直接平均。【显·SCN-014 §范围外/必须回放】

## 类7 · 查询与校验（第 25–29 句）

17. 「异常三维矩阵」查询：按 渠道×环节×类型 聚合异常分布与状态（检测中/已定位/处置中/已关闭/`unresolved_location`/`residual_anomaly`）；聚集信号单独列出待系统性诊断。【显·SCN-014 §业务闭环 STG-01；矩阵格式【推】】
18. 「根因反馈追踪」查询：按 反馈建议×接收方×状态 聚合，统计 `feedback_pending` 积压与各类根因（六分类）的分布趋势；反馈采纳率是本场景核心有效性指标。【显·SCN-014 §业务闭环 STG-05/08；采纳率【推】】
19. 「异常处置时效」指标：MTTD（发现时长）/定位时长/MTTR（处置时长）/异常率趋势/重复异常率/异常导致的 GMV 损失与账号指标影响估算；双层 KPI：FLOW-03 绑定看交付异常率与履约成本，客户体验与账号健康经 `correlation_id` 移交，不背品牌结果。【显·SCN-014 §验收与经济性】
20. 「SCN-014 验收回放」清单（五必测）：①无轨迹证据的环节定位（应被证据检查拦截）；②渠道 API 故障误判为我方缺货（应被多源交叉验证拦截）；③同一异常重复处置（应被 `residual_anomaly` 拦截）；④根因反馈无人接收仍关闭 Case（应被 `feedback_pending` 拦截）；⑤跨渠道异常率被直接平均（应被口径规则拦截）。【显·SCN-014 §必须回放】
