# FLOW-09 品牌域本体试点方案

状态：v1 设计基线；DESIGN_ONLY，无生产授权、无数据接入。本文定义品牌域作为本项目首个语义底座试点的范围、切入点与产出形态。方法依据：[SEMANTIC-LAYER-STRATEGY](SEMANTIC-LAYER-STRATEGY.md)、[KNOWLEDGE-ELICITATION-29](KNOWLEDGE-ELICITATION-29.md)；场景依据：[SCN-002](../03-scenarios/SCN-002.md)。

## 1. 试点定位

品牌域是 FLOW-09 价值流的主场，且已完成最完整的设计资产链（价值流定义 + SCN-002 规格 + AGT-029 岗位 + SKL-BRAND Skill 契约 + 双层 KPI + 数据契约）。在此建首个轻量本体，验证「29 句话 → 语义契约 → Skill/场景引用」的全链路，再决定是否推广到其余 49 岗位与 19 场景。

**切入原则**（对照书 §8.1.3 优选标准）：SCN-002 属「跨域语义协同 + 规则明确 + 零外部动作」诊断型场景，是语义层价值最易验证、风险最低的切入点。

## 2. 六类核心概念域

| 概念域 | 覆盖对象 | 主要来源资产 |
| --- | --- | --- |

| 交易域 | 订单、支付、结算、退款 | FLOW-01/SCN-016 |

## 3. 试点范围（本期只做这些）

1. **术语表 v0**：品牌域高频术语 30~50 条（SKOS-lite），优先解决「Amazon 口径 vs DTC 口径 vs 内部口径」的同名异义问题；
2. **对象-关系模型 v0**：六域核心对象约 20 个 + 关键关系约 30 条（Markdown 表 + JSON Schema，不涉推理）；
3. **事理规则 v0**：SCN-002 的 5~8 条核心规则按「如果…那么…」显性化（如「若 Amazon 覆盖率 < X 且 DTC 增长 > Y，则判定为覆盖缺口」——阈值待企业数据回填）；
4. **权限语义声明 v0**：FLOW-09 Service Identity/Scope 的语义化补充（主体/客体/条件/时效四元组）；
5. **Skill 依赖声明**：SKL-BRAND-* 契约增加 `ontology_dependencies` 字段（引用术语表条目 ID）。

**不做**：不建语义数据库、不写 RDF/OWL 文件、不动真实数据契约字段、不扩展到非品牌域。

## 4. 切入点：AGT-029 + SCN-002 试填

用「29 句话」模板做两份试填，验证模板可用性：

### 4.1 AGT-029 立言岗位（类1/3/4/5/6）

- 类1：立言的业务对象 = 品牌定位、传播内容、渠道触点、品牌资产指标；
- 类3：术语对齐重点——「品牌资产」内部口径 vs 书2 五要素 vs L2 KPI 指标的映射；「覆盖缺口」的 Amazon/DTC 双口径；
- 类4：控制规则——「重大品牌承诺和危机表态仅使用已审批内容和外发策略；缺策略时冻结外发」（岗位 boundary 的规则化）；
- 类6：权限策略——外发动作的审批链与冻结条件。

### 4.2 SCN-002 覆盖缺口诊断（类1/2/4/7）

- 类1/2：诊断对象（品类/市场/渠道/人群段）与属性约束（覆盖率、渗透率口径）；
- 类4：事理规则——信号触发条件、证据充分性判据、机会判断的可证伪标准；
- 类7：查询模板——「Amazon vs DTC 覆盖缺口」的固定取数与计算口径。

**试填产出**：两份语义契约草稿已产出——[SEMANTIC-CONTRACT-AGT-029](SEMANTIC-CONTRACT-AGT-029.md)（类1/3/4/5/6，20 条）与 [SEMANTIC-CONTRACT-SCN-002](SEMANTIC-CONTRACT-SCN-002.md)（类1/2/4/7，18 条），均为 v0.1-draft 待用户逐条评审；评审通过后升为 v0 基线。

## 6. 验证与门禁

- **模板验证**：两份试填能否用 29 句话无遗漏覆盖岗位职责与场景事理——覆盖度 <80% 则回修模板；
- **引用验证**：SKL-BRAND 契约的 `ontology_dependencies` 能否被机器解析且引用闭合；
- **门禁关系**：本试点产出物属设计资产，不改变 PILOT-G0~G4 状态；G1 数据就绪后，语义层作为诊断 Case 的输入规范被消费。
- **成功标准**：SCN-002 影子 Case 运行时，AGT-029 能引用语义契约完成诊断，而非依赖临时口径解释——这是 P2 影子运行的前置质量条件。

## 7. 风险

- 术语表依赖用户（业务专家角色）确认——试填草稿须经用户逐条评审，不得自行定稿；
- 阈值类规则（覆盖缺口判据）在企业数据回填前只能是占位符，须显式标注 `pending_data`；
- 试点范围克制：六域 20 对象是上限，超出则拆分下一迭代。
