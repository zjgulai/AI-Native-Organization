# B 层执行面设计 v0.1（产品层）

状态：**v0.1 基线**（2026-11-24 评审通过）。DESIGN_ONLY，不构成业务授权、店铺连接或凭证托管。本文件是 [SEMANTIC-PERMISSION-V01](SEMANTIC-PERMISSION-V01.md) PV-21「受控执行面」的**产品形态定义**——语义层已定「模型无执行通道、B 层只能经客户确认后由受控执行面落地」，本文件定义这个执行面具体是什么。依据：用户对 R4 四问决策（D-080 已录 DECISIONS.md）：①执行面=C 分层混合；②确认粒度=分级确认；③Emergency Guard=标准档；④执行包规范一并定义。

来源标注：【显】=v5 产品规划/场景规格/权限语义已定义；【推】=本文件归纳待评审；【数】=阈值待客户规则集回填。

## 1. 决策背景

- v5 产品边界声明：「开店建站、发布、提交、退款、投诉等对外动作只出方案和草稿，**由客户执行**」——首期执行面按手动交接理解；
- PV-21 deny 规则要求 B 层动作「经客户确认后由受控执行面落地」，但未定义执行面形态——本文件补齐；
- 117 项工作 A/B 授权映射（SEMANTIC-WORK-AUTH-V01）中 B 层 23 项全部依赖本执行面才能闭环；
- SCN-018 Emergency Guard 快速通道需要 Policy Gate 预定义最小保护动作清单——本文件 §4 给出标准档。

## 2. 执行面三层模型（决策①：C 分层混合）

| 层 | 名称 | 覆盖动作 | 状态 |
| --- | --- | --- | --- |
| **ES-M** | 手动交接面 Manual Handoff | 全部 B 层动作的默认执行面 | **v0.1 基线** |
| **ES-A** | API 受控执行面 API Executor | 低风险且平台 API 成熟的动作子集 | 演进路径，另案评审 |
| **ES-X** | 永久人工面 | 高风险子集（见 §3.3） | 永久边界，不进 API 面 |

### 2.1 ES-M 手动交接面（v0.1 唯一执行面）

链路：`Action Intent → 客户确认（§3）→ 执行包生成（§5）→ 客户在平台后台手动执行 → Sage 只读回核验（SP-01）→ Action Receipt（PV-28）`

- **零写凭证**：Sage 不持有任何店铺写权限；SP-05/SP-06 在首期仅作为「执行包参数来源+回读核验源」存在；
- **平台无关**：不依赖各平台 API 能力差异，Amazon/TikTok/Shopify 同构可用；
- **Receipt 由回读生成**：客户执行后，Sage 经已连接店铺数据（PV-01）读回目标状态与参数哈希比对，一致则闭环，不一致标 `execution_mismatch` 进入复核；客户可在执行包上回执「已执行/无法执行/执行结果不同」三态；
- **时效约束**：执行包带有效期【数：默认建议 72h】，超期未执行自动标 `expired` 需重新确认（参数可能已漂移）。

### 2.2 ES-A API 受控执行面（演进路径）

链路：`Action Intent → 客户确认 → Policy Gate 判定 → Execution Broker 调平台 API → API 回执 → Action Receipt`

- **启用前提**（全部满足才可对某平台×动作类开放）：①该平台 API 能力评估完成（Shopify Admin API 成熟为首选候选）；②客户 OAuth 授权 scoped token（权限最小化到单动作类）；③凭证托管方案评审通过（KMS/加密/审计）；④该动作类连续 N 次【数】ES-M 执行零 `execution_mismatch`；
- **候选动作类**（API 成熟度评估后逐类开放）：PV-11 listing 内容、PV-12 改价（高于底线时）、PV-13 库存、PV-14 广告预算（低于阈值时）、PV-15 单条评价/客服回复；
- **不候选**：PV-16 寄样、PV-17 批量触达、PV-18 开店备案、PV-19 资金申报类——见 §3.3。

### 2.3 ES-X 永久人工面

以下动作**任何版本都不开放 API 直执**，永远走 ES-M 手动执行包：

- PV-16 寄样/达人建联（实物+对外承诺）、PV-17 批量触达（批量对外）、PV-18 开店/备案（账号级）、PV-19 资金类申报（赔偿/拒付/结算争议）；
- PV-12 低于成本底线、PV-14 超预算幅度阈值的逐对象审批子集；
- 理由：法律性承诺、资金、实物、批量外发的错误成本远高于自动化收益；平台 API 对此类动作的支持度本身也最差。

## 3. 确认流分级（决策②：分级确认）

### 3.1 分级规则

| 确认级 | 覆盖动作 | 确认方式 |
| --- | --- | --- |
| **C1 标准级** | PV-11、PV-13、PV-15；PV-12/PV-14 未触阈值部分 | **审核会话批量**：客户在一个确认界面逐条过目 Intent（动作+对象+参数+diff），可逐条批准/驳回/修改，整批提交；每条仍独立绑定动作+对象+参数哈希（PV-20/PV-27 语义不变） |
| **C2 高风险级** | PV-16/17/18/19 + PV-12 触底线 + PV-14 超阈值 | **逐条单独确认**：每个 Intent 独立确认页，须显式勾选参数摘要+风险提示，无批量路径 |
| **C3 规则级** | SCN-018 Emergency Guard 最小保护动作 | **不走逐动作确认**：授权在 Policy Gate 规则发布时一次性给出（§4），动作执行时模型外组件直执；客户可随时撤销规则版本 |

### 3.2 C1 审核会话语义约束

- 会话内每条 Intent 展示：动作类、对象（店铺×Listing/订单/评价等）、参数 diff（改前→改后）、依据版本（SP-02/SP-03）、数据快照时间（PV-25）；
- 客户可对单条修改参数——修改后参数哈希重算，按新哈希确认；
- 会话有效期【数：建议 24h】；未确认 Intent 到期标 `expired` 不自动执行；
- 批量提交≠批量授权：每条批准记录独立 Action Receipt，可单独追溯与撤销（已执行的走平台侧撤销评估）；
- 「沉默即通过」「默认勾选」「整类免确认」在 C1/C2 均不存在（PV-27 不变）。

### 3.3 高风险触发判定

- PV-12：拟改价低于客户规则集价格底线【数】→ C2；
- PV-14：预算变动幅度超客户规则集阈值【数】→ C2；
- 判定在 Intent 生成时执行，结果随 Intent 标注 `confirm_tier`；客户不可在确认界面降级 C2→C1。

## 4. Emergency Guard 最小保护动作清单（决策③：标准档）

Policy Gate 预定义、模型不可扩展；仅在 D-026 触发条件成立（确定性规则命中+唯一 Case 绑定）时执行；每次执行产生 Action Receipt 并通知客户。

| ID | 动作 | 执行面 | 可逆性 | 说明 |
| --- | --- | --- | --- | --- |
| EG-1 | 标记待人工复核+通知 | 内部（不写平台） | — | Case 标记 `eg_flagged`、通知客户与值班人；零外部副作用，永远第一动作 |
| EG-2 | 暂停关联促销/广告活动 | ES-M 生成执行包→客户确认后执行；EG 路径下由 Policy Gate 预授权直执【推：待 ADR-0010 对齐确认】 | 平台侧可恢复 | 防止账号暂停期间资金继续消耗（对应 SCN-018 `orphaned_action` 场景）；范围限「与违规信号时间线重叠的在投活动」 |

**明确不在清单**：恢复类动作、扩大类动作、listing 下架/修改、账号级操作、任何资金动作——模型与 EG 均不得执行；账号级冻结语义由 SCN-018 契约管理（冻结 Action Intent 提交，非平台写入）。

**规则治理**：清单版本化（Policy Gate 配置版本）；新增/修改清单动作须客户书面确认后发布；EG-2 的「关联」判定规则（时间窗重叠+活动-违规关联度）须在规则集中显式定义【数：关联判定参数待回填】。

## 5. 执行包字段规范（决策④）

ES-M 面向客户的「执行包」是 B 层动作的交付载体，字段如下：

| 字段 | 内容 | 约束 |
| --- | --- | --- |
| `pack_id` / `intent_id` | 执行包与 Action Intent 标识 | 一一对应，不可复用 |
| `action_class` | PV-11~19 动作类 | 决定确认级（C1/C2）与 ES-X 边界 |
| `platform` / `store_ref` | 目标平台与店铺 | 须为已连接店铺（PV-26 撤权即冻结） |
| `object` | 对象类型+平台原生 ID+可读名 | 与 Intent 参数哈希绑定 |
| `params` | 须录入平台的精确值（字段名+值） | 敏感参数脱敏展示、确认时全量哈希 |
| `steps` | 平台后台操作步骤（有序） | 按平台 UI 版本化；含入口路径与表单位置 |
| `prerequisites` | 执行前置条件 | 如「Listing 草稿已存在」「余额充足」；不满足则包不可执行 |
| `verification` | 回读核验定义 | 期望状态+读取源（SP-01 数据域）+容差窗口【数】 |
| `rollback` | 撤销指引 | 平台支持处给出；不支持标 `irreversible` 并升级确认级 |
| `receipt_template` | 客户回执模板 | 已执行/无法执行/结果不同三态+备注位 |
| `issued_at` / `expires_at` | 生成与有效期 | 默认 72h【数】；超期 `expired` |
| `basis_refs` | 依据版本引用 | SP-02/SP-03 版本号，供 PV-29 规则锚定 |

## 6. 与语义层的接口（不改语义，只落地）

- PV-10 `propose.action_intent` 产出 Intent → 本文件定义其下游；
- PV-20 `confirm.action` 确认绑定 → C1/C2/C3 三种确认通道均满足「动作+对象+参数哈希」绑定；
- PV-21 deny 维持：S-SG 永不直执；ES-A 启用后执行主体是 Execution Broker（模型外组件），非 S-SG；
- PV-28 Receipt：ES-M 由回读核验生成、ES-A 由 API 回执生成、EG 由 Policy Gate 生成——三类 Receipt 同构；
- PV-29 规则锚定：执行包 `basis_refs` 与 EG 清单版本均满足版本引用要求。
