## 类1 · 对象与属性（第 1–4 句）

1. 「市场机会判断包」（Decision Package）是 SCN-002 的最终产物（业务实体），它有：候选细分/机会点列表、每条结论的证据强度分级、可证伪条件、建议验证方式（指向下游场景）、所需数据缺口。【显·SCN-002 §业务闭环 STG-05】
2. 「市场机会判断包」的字段类型：候选细分=对象列表、机会点=文本+证据引用、证据强度=枚举分级【数·分级刻度待定】、可证伪条件=文本、验证方式=场景引用（SCN-011/013 等）、数据缺口=列表。【显·结构来源 SCN-002；分级刻度【推】】
3. 「诊断对象」与「业务对象」的关系：场景业务对象为品牌、品类、目标市场/渠道、竞品集合、消费者人群段五类；诊断对象是其在 Case Charter 中实例化的具体范围（品牌×品类×市场×时间窗）。【显·SCN-002 §经营目的与范围/STG-02】
4. 「SCN-002 Case」的生命周期状态沿八阶段协议：STG-01 信号接收 → STG-02 建单 → STG-03 上下文装配 → STG-04 证据与诊断 → STG-05 方案产物 → STG-06 Assurance 门禁 → STG-07 受控动作 → STG-08 核验与关闭；本场景 STG-07 通常为 NoActionRecord。【显·SCN-002 §业务闭环】

## 类2 · 分层与约束（第 5–8 句）

5. 「渠道」属于「市场触点」上位概念，当前枚举为 Amazon、Shopify DTC（独立站）、其他平台、B2B；Amazon 与 DTC 在数据可得性上互斥分层——「可分析/可触达」两级建档，不混用。【显·SCN-002 §输入；FLOW-09 资产链】
6. 「证据强度分级」的合法取值为三级来源标注的组合：【实测 / 书中报告 / 假设】——量化表述必须三选一标注，禁止无标注量化。【显·SCN-002 §验收与经济性】
7. 「品牌资产指标」的统计口径以 FLOW-09-DUAL-KPI-CATALOG 为唯一来源：L2 六项（认知/考虑度/SOV/渗透/复购/价格感知）各有来源、归因窗口（6–24 个月）与置信度前提；Amazon 侧复购/认知等多为受限口径，须标注不可触达。【显·FLOW-09-DUAL-KPI-CATALOG】
8. 「品类边界」约束：Momcozy 试点锁定可穿戴式吸奶器主品类；配件/内衣属关联销售，单独标注，不计入主品类覆盖/渗透口径。【显·FLOW-09 试点章程；SCN-002 适用说明】

## 类4 · 控制规则（第 12–16 句）

12. 当出现以下信号之一时触发建单评估：品类搜索趋势异动、竞品 Listing/内容/广告重大变化、评论情绪拐点、社媒话题爆发、差评率越阈；同 `case_dedupe_key` 命中直接关联既有 Case，不重复建单。【显·SCN-002 §触发；越阈数值【数】】
13. 当数据源凭据/权限缺失、口径冲突未决、输入超出 Case Charter 范围、关键来源过期且无法补齐、推断依赖未批准外部断言时，冻结相关结论分支；其余结论可独立验收。【显·SCN-002 §授权与例外/接管与恢复】
14. 如果输入满足「来源齐全率 100% + 版本固定 + 口径一致」，那么可形成机会判断；如果不满足，缩小结论范围并在 Diagnosis Record 中标注事实/假设/反证/不确定性，不猜测填充。【显·SCN-002 §业务闭环 STG-04/验收】
15. 「口径冲突」触发规则：AGT-045 判定口径冲突时冻结相关结论而非取平均；系统性口径错误移交 SCN-020 处理。【显·SCN-002 §责任与参与者/接管与恢复】
16. 禁止：发布内容、调整预算、改商品、触达客户；外部动作只能以 Action Intent 形式移交下游场景 Case（如 SCN-011/013），不在本 Case 内执行。【显·SCN-002 §范围外/STG-07】

## 类7 · 查询与校验（第 25–29 句）

25. 要回答「Amazon vs DTC 覆盖缺口」，需要按 渠道×品类×人群段 三维聚合覆盖信号：Amazon 侧取品类搜索词/BSR/份额代理，DTC 侧取 Shopify 流量/转化/CRM 细分，输出覆盖矩阵与缺口清单（对接 SKL-BRAND-01）。【显·SCN-002 §输入；SKL-BRAND-01；字段级取数【数】】
26. 「覆盖率/渗透率」计算公式待数据契约字段确认后回填；数据质量前提是 DQ-F09 十规则与 F09-DC 十用例通过。【数·pending_data；框架显·FLOW-09-DATA-CONTRACT】
27. 「Evidence Pack」验收判据：来源齐全率 100%、每条带来源/版本/新鲜度/冲突/缺口标注；常见失败原因：来源未版本化、口径混用、书中数据当实测。【显·SCN-002 §验收与经济性】
28. 「口径冲突核验」方法：同一指标在不同源出现分歧时，记录分歧双方口径与来源，以 AGT-045 口径字典为仲裁；差异容忍度【数】。【显·方法来源 SCN-002；容忍度 pending_data】
29. 「SCN-002 验收回放」清单（四必测）：①证据充分但结论被证伪——检查推断链；②数据口径冲突被静默取平均——应已冻结；③书中量化倍数被当作 Momcozy 实测引用——应被 Assurance 拦截；④Amazon 数据被当作可触达数据使用——口径违规。【显·SCN-002 §验收与经济性】
