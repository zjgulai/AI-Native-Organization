# 权限语义声明 v0.1-draft（轻量语义层）

状态：**v0.1 基线**（2026-11-24 用户逐条评审通过：24 四元组+5 规则全过）。DESIGN_ONLY，不构成业务授权。本声明是 [SEMANTIC-PERMISSION-V0](SEMANTIC-PERMISSION-V0.md) 的**域扩展版**：v0 的 24 条四元组继续管 FLOW-09 品牌域内部试点（Momcozy 企业侧），本版新增**产品层 Sage 的双层授权模型**——覆盖产品规划 v5 全部 117 项工作与两个执行型标杆（Shopify 矩阵 51 项 / VOC 洞察 7 项）。依据 [D-079](../00-project/DECISIONS.md)：首个产品标杆为执行型，权限语义须演进出「读取和出草稿自动、对外动作客户确认」的双层授权。

来源标注：【显】=权威文档已定义；【推】=本声明归纳待评审；【数】=待数据/规则源回填。

## 1. 双层授权模型（核心新增）

产品层把「授权」从内部四元组升级为**两层动作分级**，每个 WorkItem/SubScenario 的每项动作必须落入且仅落入一层：

| 层 | 名称 | 覆盖动作 | 授权方式 |
| --- | --- | --- | --- |
| **A 层** | 自动层 auto | 读取已连接店铺/平台数据；生成草稿、分析、监控报告、合规预检结果 | 范围包内默认允许；产物带草稿水印 |
| **B 层** | 客户确认层 confirm | 写入店铺（上架/改价/改库存/改 Listing）；对外动作（回复评价/客服答复/寄样/达人建联/邮件触达）；资金相关（广告预算变更/赔偿申请/拒付应诉提交）；账号级动作（开店/品牌备案提交） | **逐动作客户确认**+Action Receipt；高风险子集逐对象审批 |

**高风险子集（B 层内再加一道）**：涉及钱、实物、法律性文件、批量对外触达、定价越底线的动作，须**逐对象审批**而非批量确认——阈值（预算变更幅度、触达批量、价格底线）待客户规则集回填，当前以类别标注。

**设计原则**：A 层不产生任何外部副作用；B 层无任何「默认同意」「沉默即通过」「包月授权」——每次确认绑定具体动作+对象+参数哈希。

## 2. 产品侧主体（subject）

| ID | 名称 | 定义 | 与 v0 主体关系 |
| --- | --- | --- | --- |
| S-CU | 客户/店铺所有者 | 授权来源与 B 层唯一确认人；配置店铺连接、规则集、授权范围 | 产品侧新增；v0 无对应（v0 面向内部企业） |

| S-OP/S-MS/S-SI | （沿用 v0） | FLOW-09 内部试点主体 | **继续有效**，见 SEMANTIC-PERMISSION-V0，本版不重复定义 |

## 5. 跨源统一规则（产品侧）

| ID | 规则 | 口径 |
| --- | --- | --- |
| PV-25 | 快照时效 | 店铺数据按快照消费；决策产物须标注数据截止时间；超期数据标 stale 不作新决策依据 |
| PV-26 | 范围漂移冻结 | 店铺连接撤权/凭证失效→该店铺 SP-05/SP-06 全部 B 层动作冻结；A 层读取降级为最后快照并标 stale |
| PV-27 | 确认不沉淀 | 每次 B 层确认绑定单次动作+对象+参数哈希；**不存在**「本月同类自动同意」「默认勾选」；客户可显式授予规则化自动（未来版本另案） |
| PV-28 | Receipt 必填 | 每个 B 层动作产生 Action Receipt（确认人/时间/参数哈希/执行结果）；A 层产物带草稿水印可区分 |
| PV-29 | 规则版本锚定 | 动作执行须引用规则与授权（T-OP-36）版本；规则变更不溯及既往动作；版本不一致时按新版本重新确认 |

## 6. 与 v0 内部权限的关系 + 标杆分类

- **v0 继续有效**：FLOW-09 内部试点的 24 条四元组不变；本版产品侧四元组（PV-*）与 v0（P-*）**并行不合并**——主体、客体、激活前提完全不同，未来产品实例化时再评估收敛；
- **标杆工作分类**（执行型标杆的落地映射）：
  - **Shopify 矩阵 51 项**：读数/监控/草稿类→A 层（约占多数，如每日巡检、周报、方案草稿）；写店/对外类→B 层（如上架、改价、广告提交、邮件触达）；
  - **VOC 洞察 7 项**：分析与建议→A 层；若含对外回复/触达动作→对应 B 层条目；
  - 分类以「动作是否产生外部副作用」为唯一判据，不以工作项名称判断；
- **升级路径**：B 层高频低风险动作（如评价回复模板）在客户显式授权规则化自动后可迁入 A 层——属 v0.2 另案评审，不在本版范围。

## 7. 边界声明

- 本声明为**设计态授权语义**：不表示任何店铺已连接、不表示任何写权限已开启、不构成业务授权；
- 全部授权位默认关闭；SP-05/SP-06 在客户逐店配置+逐动作确认前不可用；
- 阈值类条件（预算幅度、触达批量、价格底线、应诉时限）一律标【数】待客户规则集/平台规则源回填，不固化数值；
- 平台侧具体权限粒度（各平台 API 能力差异）待平台接入评估，不在本语义层展开；
- 评审通过后状态升 v0.1 基线，semantic.html 同步登记。
