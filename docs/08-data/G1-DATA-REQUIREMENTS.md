# G1 数据需求文档（企业侧交付清单）

状态：**v0.1 基线**（2026-11-24 评审通过）。DESIGN_ONLY。本文把语义底座全部 `pending_data`/【数】项与试点开放项，转成**企业侧可执行的数据需求清单**——每项含数据内容、粒度/时效、PII 边界、获取方式建议、解锁的语义资产。配套：[FLOW-09 数据契约](FLOW-09-DATA-CONTRACT.md)（五源 15 数据集+DQ-F09 十规则）、[服务身份与 Scope](FLOW-09-SERVICE-IDENTITY-SCOPE.md)（五源 EXPORT_OPERATOR 范围包）、[阶段门评审](../12-rollout/FLOW-09-PILOT-GATE-REVIEW.md)（G1A/G1B 分层）。

**读者**：企业侧数据/运营/IT 接口人。**用法**：按 §1~§2 逐项确认可得性与导出方式，回填「状态」列；全部确认后进入 PILOT-G1 分源验收。

## 5. 验收标准（汇总）

- **分源验收**：每源通过 §1/§2 对应行的全部「企业侧待办」+ 证据包六要件（§1 末行）；DQ-F09 十规则全过。
- **影子运行前置**：G1A+G1B 至少各一源通过 → SCN-002 Case 可影子运行；出海产品层源按 §2 优先级分批接入，不阻塞 FLOW-09 试点。
- **回填闭环**：每解锁一项 pending_data，在对应契约「评审记录」标注数据来源与日期；全部回填后事理规则显性化产出 v0。

## 6. 建议推进顺序

1. **本周可启动**：§4 客户规则集（纯书面确认，无技术依赖）+ §1-1 Shopify 导出样例（最高频源）。
2. **G1A 批次**：Shopify 五数据集 + 社媒账号清单 + DME 产品线导出方式确认。
3. **G1B 批次**：Amazon 四报表样例 + 竞品工具字段盘点。
4. **出海层 P0 批次**：§2.1 结算源 + §2.3 VOC 源 + §2.4 合规台账 + §2.6 账号健康——这四组解锁 SCN-016/S4/S5 高频工作。
5. **出海层 P1/P2**：广告、履约、达人、分层、多平台源按产品标杆（Shopify 矩阵/VOC）实际开通范围裁剪——**不必一次全量**。
