# SCN-007：需求预测、补货与库存调拨

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-03（供需：补货、采购与交付）绑定时为 AGT-016 知量；FLOW-01（存量GMV）绑定时为 AGT-021 北辰。依据：D-025、D-078、PB-003、[品牌增长方法论](../06-playbooks/BRAND-GROWTH-METHODOLOGY.md) 第 4 节「渠道购买场」。

适用说明：本场景是「货架不断货」与「库存不压资金」的平衡器——缺货直接损失 GMV 与客户体验（下单失败=品牌资产折损），过剩则占用现金流（母婴品类季节性强、生命周期有限）。FLOW-03 绑定时 AGT-016 知量对「供应计划与可售库存对齐」负责；GMV 影响经 `correlation_id` 关联 FLOW-01 Case。库存预留与采购承诺只复用业务系统权威记录与回执，不允许 AI 自行承诺。

## 经营目的与范围

把需求预测与补货转化为**有置信度区间、有约束校验、有回执闭环的库存决策包**，在服务水平与资金效率之间找到可解释的平衡点。

- 业务对象：SKU×渠道×仓库存水位、需求预测（历史销量+季节性+促销+新品爬坡）、补货建议（采购量/调拨量/时点）、库存预留（大促/渠道配额）、呆滞与库龄处置；不含采购合同谈判（SCN-006/FLOW-03 上游）、跨境运输执行（SCN-008）、定价清货决策（SCN-010）。
- 范围内：库存信号监测 → 需求预测更新 → 补货/调拨建议 → 约束校验（资金/仓容/供应商产能/渠道规则）→ Action Intent（采购单/调拨单/预留）→ 到货与上架回执核验 → 预测准确率回流。
- 范围外：不直接下采购单/调拨单（当前无授权，全部 `NoActionRecord` 或 Action Intent）；不做供应商选择与合同（SCN-006）；不做清货定价（SCN-010）；不做渠道库存映射配置（FLOW-04/渠道运营）。
- 不适用：新品无历史销量（用类比品+爬坡模型，置信度强制低）；单一渠道无库存数据接口（先建数据接入）；季节性品类非旺季（降级为常规监测）。

## 触发与输入

### 触发

- 经营节奏：周度补货会、月度库存健康检查、季度预测模型回顾、大促前专项备货。
- 信号触发：库存水位跌破安全线、预测偏差超阈值、供应商交期异常、渠道库存映射不一致、大促备货窗口开启、库龄恶化。
- 结构触发：同一 SKU 多渠道库存分配冲突、预测持续偏高导致积压、预测持续偏低导致频繁缺货、季节性切换期预测失真。

## 业务闭环

1. **STG-01 信号接收**：库存水位、预测偏差、供应链异常、促销窗口分别建档；缺货风险与积压风险分流。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-03 为主，FLOW-01 关联不兼）、主场景 SCN-007、范围（SKU 集合/渠道/仓/周期）、服务水平与资金约束声明。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载需求预测与库存优化 Skills；只读销量/库存/供应链/渠道工具；促销与新品计划版本。
4. **STG-04 证据与诊断**：业务贡献方产出 Inventory Evidence Pack（库存快照、销量序列、在途、供应商产能、渠道映射、促销计划）；诊断输出预测区间（非点值）、缺货风险 SKU 清单、积压风险 SKU 清单、约束冲突点；区分「需求波动」（真实需求变化）与「预测误差」（模型偏差）。
5. **STG-05 方案产物**：「补货调拨行动包」——逐 SKU 补货建议（数量/时点/渠道分配）、调拨建议、库存预留方案、呆滞处置建议（移交 SCN-010 定价或 SCN-006 供应商）、约束校验结果；每条标注置信度与可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（服务水平约束、资金上限、仓容上限、MOQ/产能约束、schema、口径一致）+ AGT-005 语义复核（预测区间是否过度精确、约束是否遗漏、渠道分配是否与规则一致）。
7. **STG-07 受控动作**：获批方案拆为 Action Intent——采购单建议、调拨单建议、渠道预留；当前阶段全部 `NoActionRecord` 或内部审批 Intent。
8. **STG-08 核验与关闭**：到货/上架/可售回执核验；预测准确率回流模型；库存健康复盘（缺货率/周转/呆滞）；关闭后学习提取回流（哪些品类预测偏差大、哪些约束常被忽略）。

## 授权与例外

- **允许**：只读销量/库存/供应链/渠道数据；产出预测、建议、Action Intent 与约束校验；跨 Case 引用已验收 Artifact。
- **冻结条件**：库存数据实时性不足且无法交叉验证；供应商产能/交期数据缺失；渠道库存映射不一致未裁决；资金/仓容约束未量化；促销计划版本冲突。
- **高风险动作分级**：超 MOQ 最小起订量、占用资金超预算比例、渠道间大规模调拨、涉及清货处置——逐对象单独审批。
- **歧义处理**：预测置信度不足时给区间并标注 `low_confidence` 而非强行给点值；渠道库存映射冲突时以仓库实物为准并标注 `mapping_conflict`。
- **重复与部分失败**：同一 SKU×周期跨 Case 重复预测时关联既有 Case 更新；部分数据源缺失时对应维度标 `unknown` 降低置信度；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；发现预测系统性偏差导致错误补货；供应商重大交期延误；渠道规则变更导致库存策略失效。
- 冻结范围：仅冻结受影响 SKU/渠道/仓；已提交的采购/调拨建议由执行 Case 管理，本 Case 只引用回执。
- 已产生外部效果：采购单、调拨单、渠道预留——需回执可对账；补货已下单但需求骤降的标 `overstock_risk` 进入 SCN-010 清货评估。
- 恢复：冻结解除后从断点继续；Inventory Evidence Pack 版本化保留；预测模型版本更新后既有建议标记 `needs_revalidation`。

## 验收与经济性

- **产物验收**：Evidence Pack 四源齐全率 100%；每个补货建议带预测区间、约束校验结果与置信度；缺货/积压风险 SKU 均有处置路径；渠道分配与规则一致。
- **经营指标**：缺货率、库存周转天数、预测准确率（MAPE/偏差率）、呆滞库存占比、库存占用资金、补货建议采纳率。
- **双层 KPI 关系**：本场景是**体验与 GMV 的交汇点**——缺货损失当期 GMV（FLOW-01 关联）也损失客户体验（FLOW-05 关联）；品牌资产影响（断货=心智折损）经 `correlation_id` 移交 FLOW-09。库存积压的清货对价格感知的影响移交 SCN-010。
- **经济性门槛**：首个周期以「预测模型回测准确率达标 + 至少一轮补货建议被采纳执行 + 缺货率/周转指标改善可测」为验收前提。
- **必须回放**：预测给点值而非区间（应被置信度规则拦截）；约束校验遗漏资金上限（应被确定性校验拦截）；渠道库存映射冲突时仍按系统值补货（应被 `mapping_conflict` 规则拦截）；新品无历史销量却给高置信度预测（应被新品规则拦截）；补货建议被当作采购承诺（应被权威记录规则拦截）。
