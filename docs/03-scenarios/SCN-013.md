# SCN-013：独立站体验、转化与复购

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-09 绑定时为 AGT-029 立言；FLOW-01（GMV）绑定时为 AGT-023 自航；FLOW-05（客户旅程）绑定时为 AGT-034 续缘——一张 Case 只绑定一条主价值流（D-025）。依据：D-078、PB-009、[品牌增长方法论](../06-playbooks/BRAND-GROWTH-METHODOLOGY.md) 第 6 节「用户数据资产」与第 5 节「体验即资产」、书2 第 8/18/21/24 章框架。

适用说明：本场景横跨三条价值流是刻意的——同一「独立站转化问题」可被拆为品牌资产 Case（FLOW-09，主结果=体验资产与LTV）与 GMV Case（FLOW-01，主结果=当期订单），通过 `correlation_id` 关联、状态独立，不合并为一个 Case。

## 经营目的与范围

把独立站（Shopify DTC）的体验问题转化为**可证伪的改进假设与实验结论**，同时积累可分析、可触达的用户数据资产。

- 业务对象：独立站页面/漏斗、SKU 集合、用户人群段、CRM 触达链路；不含 Amazon 端体验（受平台限制，走 SCN-009/021-022 路径）。
- 范围内：行为与 VOC 信号聚合 → 体验诊断 → 改进假设 → 实验设计 → 效果核验 → 复购/资产指标回流。
- 范围外：不直接改站点页面、不发邮件/短信、不调整价格——所有站点与触达动作只能以 Action Intent 移交执行 Case（当前 Shopify 绿地约束 D-050/D-051 下全部为 `NoActionRecord` 或文档级设计）。
- 不适用：Amazon 渠道问题；纯客服工单处理（FLOW-05/SCN-015）；无自有流量的冷启动站点（先补流量再谈转化）。

## 触发与输入

### 触发

- 经营节奏：月度/季度独立站经营复盘前的例行 Case；新品上市后 30 天体验基线建立；大促后归因复盘。
- 信号触发：转化率/复购率/LTV 趋势拐点、购物车放弃率异常、退货原因聚类变化、CRM 触达疲劳信号、页面性能劣化。
- 资产触发：可分析/可触达数据覆盖率盘点（书2 ch24）、用户分层标签缺口。

### 输入

| 输入类 | 来源（候选，待确认接入） | 质量要求 |
| --- | --- | --- |
| 行为数据 | Shopify Analytics、站点埋点、热力图工具 | 事件级或会话级，带一致匿名 ID；AGT-045 口径契约内 |
| 交易数据 | 订单、退款、AOV、复购间隔 | 45 天加密保留政策（D-048）适用的字段级；原始订单不出 Connector |
| VOC | 评论、客服记录、退货原因、社媒提及 | 原文级+渠道+时间戳；Amazon 评论只作品类信号不混 DTC 结论 |
| CRM 数据 | 邮件/短信触达记录、优惠券使用、会员分层 | 可触达数据单独建档，不与可分析数据混算 |
| 实验历史 | 历史 A/B 与增量评估产物 | 只引用已验收 Stage Artifact |
| 品牌基线 | 品牌资产指标现状、品牌定义版本 | 对齐 BRAND-GROWTH-METHODOLOGY §5 |

输入按「可分析 / 可触达」两级建档：独立站是唯一两级兼备的渠道，Amazon 数据只可分析受限——两级数据分别建模，结论不混用。

## 当前基线

## 业务闭环

1. **STG-01 信号接收**：行为/VOC/交易信号按周聚合成 Signal Envelope；趋势拐点与节奏复盘分别建档。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-09/01/05 之一）、主场景 SCN-013、对应结果负责人、业务范围（页面/人群/时间窗/SKU 集）与完成条件。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载体验诊断 Skills（SKL-BRAND-01 覆盖审计、SKL-BRAND-02 归因设计按需）、只读数据工具与品牌定义版本。
4. **STG-04 证据与诊断**：AGT-023/034/038 产出 Experience Evidence Pack（漏斗断点、VOC 聚类、复购曲线、可触达覆盖率）；结果负责人形成 Diagnosis Record——区分事实、假设、反证；体验问题按书2「体验即资产」分级（基础型/期望型/兴奋型，KANO 逻辑）。
5. **STG-05 方案产物**：「体验改进与实验包」——候选改进假设（含预期影响的双层指标）、实验设计（分组/样本量/最短周期/停止条件）、所需数据缺口；每条标注可证伪条件与 GMV 护栏。
6. **STG-06 Assurance 门禁**：确定性校验（schema、口径、匿名化合规）+ AGT-005 语义复核（实验是否可识别因果、样本是否足够、结论是否越界）。
7. **STG-07 受控动作**：当前阶段全部为 `NoActionRecord`——实验包移交执行 Case；若获批进入实验执行，仍由执行 Case 经 Policy Gate/Execution Broker 逐对象操作，不在本 Case 内改站点或发触达。
8. **STG-08 核验与关闭**：核对产物与成本；关闭后学习提取——被证伪假设、有效实验模式回流为品牌/体验知识资产，经 AGT-048 治理进 Skill 库。

## 授权与例外

- **允许**：只读访问已授权数据源；产出结构化诊断与实验设计；跨 Case 引用已验收 Artifact。
- **冻结条件**：Shopify/CRM 凭据或数据权限缺失；口径冲突（如复购定义不一致）未决；可分析与可触达数据被要求混算；实验设计无法满足最小可识别条件；输入超出 Charter 范围。
- **歧义处理**：建单前歧义记 Pre-Case Exception；范围内歧义在 STG-04 标注不确定性并缩小结论，不猜测填充。
- **重复与部分失败**：同 `case_dedupe_key` 关联既有 Case；Worker 产物不合格退回 STG-04 补证，不降验收标准；实验周期内数据缺口记入 Evidence Pack 缺口清单而非中断 Case。

## 接管与恢复

- 停止条件：连续两轮补证仍不满足最小输入合同；发现订单/客户数据口径系统性错误（交 AGT-045/SCN-020）；实验设计被 AGT-005 判定不可识别因果且无替代方案。
- 冻结范围：仅冻结受影响的数据源/结论分支（如 CRM 触达数据失效只冻结复购归因，不冻结漏斗诊断）。
- 已产生外部效果：本场景当前无外部副作用；未来若实验 Case 已执行改动，其回滚由该 Case 的 Recovery Contract 负责，本 Case 只引用其回执。
- 恢复：冻结解除后从断点阶段继续；Evidence Pack 与实验设计版本化保留，禁止覆盖历史。

## 验收与经济性

- **产物验收**：Experience Evidence Pack 来源齐全率 100%；每个改进假设带双层预期指标、可证伪条件与停止条件；实验设计含样本量/周期/对照逻辑；量化表述标注「实测/书中报告/假设」三级来源。
- **经营指标**：诊断→实验转化率；实验结论被采纳并产生可观测结果的比例；LTV/复购指标口径一致性；单位诊断成本（token+工具+人力分列）。
- **双层 KPI 关系**：FLOW-09 绑定时验收看体验资产与 LTV 长周期变化（不以单次转化率替代）；FLOW-01 绑定时看当期 GMV/订单，但必须同时核对品牌资产护栏是否被伤害；冲突信号（GMV 升而品牌指标降）触发 AGT-005 复核而非取平均。
- **经济性门槛**：首个 90 天以「诊断质量对齐人工基线 + 实验设计通过独立复核」为验收前提；成本优化在第二阶段。
- **必须回放**：实验组自选择偏差被当作因果（应被 AGT-035/005 拦截）；可触达数据被用于不可触达结论（口径违规）；Amazon 评论被混入 DTC 复购结论；书中 LTV 倍数被当作 Momcozy 实测引用。
