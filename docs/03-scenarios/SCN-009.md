# SCN-009：商品内容、本地化与上架

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-09 绑定时为 AGT-029 立言；FLOW-04（新市场与合规上架，BVS-04）绑定时为 AGT-024；FLOW-01（GMV）绑定时以该流结果负责人为准。依据：D-078、PB-009、[品牌增长方法论](../06-playbooks/BRAND-GROWTH-METHODOLOGY.md) 第 3 节「渠道与本地化」、书2 第 16/17/23 章框架。

适用说明：本场景是「商品信息正确性」的唯一归口——Listing 内容、本地化翻译、上架合规与市场准入判断都在这里。它与 SCN-012（品牌内容/活动）的边界：本场景管「商品卡片说了什么、说得对不对、能不能上架」，SCN-012 管「品牌故事与活动怎么讲」。与 SCN-003（产品立项）边界：本场景假设产品已立项，管上市前后的信息资产化。

## 经营目的与范围

把商品信息、本地化与上架决策转化为**正确、合规、可追溯、能反馈转化的商品资产**。

- 业务对象：商品 Listing（Amazon 标题/五点/描述/A+、独立站 PDP）、本地化语言版本、上架市场/渠道、合规资质；不含广告投放（SCN-011）与品牌 campaign（SCN-012）。
- 范围内：商品信息诊断 → 本地化与合规检查 → 上架/修改方案 → 发布执行（Action Intent）→ 转化与问题反馈。
- 范围外：不直接修改 Listing 或上架商品（当前无授权）；不做产品定义与立项（SCN-003/004）；不做定价决策（SCN-010）。
- 不适用：全新产品立项阶段（SCN-003）；纯广告优化（SCN-011）；无商品主数据（AGT-045 主数据缺失时先走 SCN-020）。

## 触发与输入

### 触发

- 经营节奏：新品上市上架、季度 Listing 优化周期、市场/渠道扩展、新品类进入评估。
- 信号触发：Listing 转化率拐点、差评/退货中信息相关原因聚类、本地化错误投诉、平台政策/合规规则变化、竞品 Listing 重大更新。
- 资产触发：品牌定义/产品事实版本更新、合规资质到期、本地化词库/风格指南缺口。

## 业务闭环

1. **STG-01 信号接收**：上架节奏、新品信号、Listing 表现拐点、合规变化分别建档。
2. **STG-02 建单**：Case Charter 固定主价值流、主场景 SCN-009、范围（SKU 集/渠道/市场/语言）、完成条件；声明品牌资产与转化双层预期。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载商品信息与合规 Skills、品牌定义与产品事实版本、只读数据工具。
4. **STG-04 证据与诊断**：AGT-021/022/023/024 产出 Listing Evidence Pack（现有内容快照、主数据差异、合规缺口、本地化质量、表现数据、VOC 聚类）；结果负责人形成 Diagnosis Record——按书2「内容五标准」（准确信息/吸睛/场景/易传播/调性一致）与「渠道购买场」（场景+媒体+渠道三位一体）诊断信息资产缺口；信息准确性问题单独分级（事实错误/夸大宣称/本地化错误/风格不一致）。
5. **STG-05 方案产物**：「上架与本地化包」——每个 SKU/渠道的 Listing 修改清单（含产品事实锚点、合规自查、本地化版本、预期双层指标）、上架/下架/修改动作序列、依赖与停止条件。
6. **STG-06 Assurance 门禁**：确定性校验（产品事实与主数据一致、合规规则匹配、语言版本完整、本地化词库引用）+ AGT-005 语义复核（功效宣称是否有证据、翻译是否改变原意、本地化是否符合目标市场文化）。
7. **STG-07 受控动作**：获批包拆为逐对象 Action Intent（每个 SKU×渠道×语言一个意图）→ Policy Gate → Execution Broker → 回执；当前阶段全部 `NoActionRecord`。
8. **STG-08 核验与关闭**：上架回执与转化/问题反馈核验；品牌资产（Listing 是否成为品牌资产载体）与转化双层归因；关闭后问题模式回流为商品信息知识资产。

## 授权与例外

- **允许**：只读商品主数据、Listing、合规规则与表现数据；产出诊断、修改方案与 Action Intent；跨 Case 引用已验收 Artifact。
- **冻结条件**：商品主数据缺失或版本冲突；合规规则库未覆盖目标市场；产品事实与 Listing 声明不一致且无法确认；本地化母语审核不可用且影响发布；输入超出 Charter 范围。
- **歧义处理**：建单前歧义记 Pre-Case Exception；范围内歧义在 STG-04 标注并**删除而非弱化**不确定的宣称（如无法证实的功效描述必须移除）。
- **重复与部分失败**：同 `case_dedupe_key` 关联既有 Case；部分渠道/语言权限缺失时只冻结该分支；Listing 被平台拒审时记入 Case Ledger 并触发合规复审。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；商品主数据系统性错误；合规资质缺失且无法确认；信息包被 AGT-005 判定系统性失实。
- 冻结范围：仅冻结受影响 SKU/渠道/语言/市场分支。
- 已产生外部效果：已上架/修改的 Listing 可回滚——由执行 Case 的 Recovery Contract 负责，本 Case 只引用回执与回滚结果。
- 恢复：冻结解除后从断点继续；Listing Evidence Pack 与上架包版本化保留。

## 验收与经济性

- **产物验收**：上架包中每个 SKU×渠道×语言有产品事实锚点、合规自查结果、本地化版本与预期双层指标；信息准确性问题 100% 标注分级；合规自查覆盖率 100%；量化效果预期标注来源。
- **经营指标**：上架→转化的可归因比例；信息相关退货/差评占比变化；本地化错误投诉率；Listing 内容资产复用率。
- **双层 KPI 关系**：FLOW-09 绑定时验收看商品信息是否成为品牌资产载体（内容质量、品牌一致性、本地化覆盖度）与长周期品牌指标；FLOW-04 绑定时看市场准入合规结果；FLOW-01 绑定时看当期转化。信息错误导致的退货/差评同时计入品牌资产损伤，不得只看转化。
- **经济性门槛**：首个周期以「上架包信息准确性 100% 经复核 + 合规通过率 100% + 每条修改可追溯到产品事实」为验收前提。
- **必须回放**：Listing 功效宣称无证据支撑被上架（应被 Assurance 拦截）；本地化翻译改变产品事实原意（应被 AGT-005 拦截）；合规资质过期后仍上架（应冻结）；Amazon Listing 被当作可触达用户数据来源（口径违规）；书中内容效果倍数被当作 Momcozy 实测。
