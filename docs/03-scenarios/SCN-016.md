# SCN-016：渠道结算、对账与财务经营

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-01（存量GMV）绑定时为 AGT-021 北辰；FLOW-03/05/06/08 绑定时以该流结果负责人为准（FLOW-03 为 AGT-016、FLOW-05 为 AGT-034、FLOW-06 为 AGT-047、FLOW-08 为 AGT-001）。依据：D-025、D-078、PB-001、PB-005。

适用说明：本场景是**五流绑定**的最广场景——结算对账是所有价值流的「财务事实层」：FLOW-01 的 GMV 声明、FLOW-03 的采购/履约成本、FLOW-05 的退款与补偿、FLOW-06 的指标口径、FLOW-08 的经营复盘都消费它的输出。按 D-025 主绑定 FLOW-01/AGT-021（GMV 真实性是其结果责任的一部分）；其余四流经 `correlation_id` 关联——本场景产出的是**对账证据包**而非各流的经营结论，各流 Case 引用证据包做自己的核算。

## 经营目的与范围

把渠道结算转化为**可解释、可对账、可追溯的财务事实链**，让 GMV、回款、费用与损益的每一分钱都有据可查。

- 业务对象：各渠道结算报表（Amazon Settlement、Shopify Payouts、Target/Walmart、DME 保险结算）、平台费用（佣金/履约费/仓储费/广告费结算）、退款与扣款、汇率折算、税费、跨渠道对账差异；不含现金流预测与资金安排（SCN-017）、预算分配决策（SCN-001）、经营分析叙事（FLOW-08 下游）。
- 范围内：结算数据采集 → 口径映射 → 差异识别与定位 → 差异处理建议 → Action Intent（差异申诉/账务调整）→ 对账闭环确认 → 经营损益解释包。
- 范围外：不直接操作财务系统/银行/平台后台（当前无授权，全部 `NoActionRecord` 或 Action Intent）；不做税务申报判断（AGT-042 合账负责税务口径）；不做经营决策建议（只解释数字不建议怎么花）。
- 不适用：结算周期未结束的期间（只能做预估标 `provisional`）；单一渠道且无历史对账差异（降级为常规月结）。

## 触发与输入

### 触发

- 经营节奏：各渠道结算周期（月结/双周结）、季度财务关账、年度审计。
- 信号触发：结算金额与订单系统不符、平台扣款异常、汇率波动超阈值、退款与结算冲突、跨渠道同一订单重复结算、费用科目口径变更。
- 结构触发：同一差异类型跨期重复出现（系统性口径问题）、结算延迟影响回款预测、平台规则变更导致费用结构变化。

### 输入

| 输入类 | 来源（候选，待确认接入） | 质量要求 |
| --- | --- | --- |
| 渠道结算报表 | Amazon Settlement Report、Shopify Payouts、各平台财务后台 | 官方报表原件级；字段口径版本化 |
| 订单与退款 | 各渠道订单系统、退款记录、取消记录 | 与结算报表逐笔可勾稽；时区统一 |

## 业务闭环

1. **STG-01 信号接收**：结算数据按「渠道×期间×币种」聚合；结算报表到达、差异告警、费用结构变更分别建档。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-01 为主，其余四流按差异归属选一，不可兼）、主场景 SCN-016、范围（渠道/期间/币种/科目）、对账精度声明（逐笔/汇总）。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载结算对账与差异诊断 Skills；只读结算/订单/退款/账务工具；费率与税率版本库。
4. **STG-04 证据与诊断**：AGT-040 组织 Settlement Evidence Pack（结算报表原件、订单勾稽表、退款明细、费用拆分、汇率记录、银行到账）；诊断将差异定位到来源——「订单-结算漏单」「费用口径变更」「退款时点差」「汇率差」「平台规则变更」「我方账务错误」「重复结算」；无法定位的标 `unreconciled`。
5. **STG-05 方案产物**：「对账结论包」——逐差异处理建议（申诉/账务调整/接受差异/待查）、经营损益解释（GMV→净回款→费用→净利的桥接表）、跨期影响标注、口径变更建议；每条标注证据引用与可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（勾稽平衡、币种一致、税率版本、schema、证据引用）+ AGT-005 语义复核（差异归因是否有报表原件支撑、桥接表是否遗漏科目、配平是否掩盖问题）。
7. **STG-07 受控动作**：获批方案拆为 Action Intent——平台差异申诉、账务调整凭证、口径映射更新建议；当前阶段全部 `NoActionRecord` 或内部审批 Intent。
8. **STG-08 核验与关闭**：差异处理回执与下期结算核验（申诉是否追回/调整是否生效）；对账结论写入财务事实层供各流引用；关闭后学习回流（哪些差异类型可自动化、哪些需要人工判断）。

## 授权与例外

- **允许**：只读结算/订单/退款/账务数据；产出对账、差异诊断、损益解释与内部 Action Intent；跨 Case 引用已验收 Artifact。
- **冻结条件**：结算报表未到或不完整；订单-结算勾稽关系无法建立；币种/税率版本缺失；平台规则变更未同步导致口径失效；银行到账记录缺失无法锚定。
- **高风险动作分级**：差异申诉（对外正式主张）、账务调整（影响报表）、跨期重述——逐对象单独审批；AI 不得出具审计意见只出具对账证据与建议。
- **歧义处理**：差异无法归因时标 `unreconciled` 进入待查队列而非配平；多渠道同现差异优先假设共同原因（汇率/平台政策）而非分别归因。
- **重复与部分失败**：同一结算期间跨 Case 重复对账时关联既有 Case；部分渠道数据缺失时只冻结受影响渠道分支；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；发现系统性口径错误导致全部差异失真；平台更正结算报表；银行到账与结算严重不符。
- 冻结范围：仅冻结受影响渠道/期间/科目；已提交的差异申诉由申诉 Case 管理，本 Case 只引用回执。
- 已产生外部效果：差异申诉、账务调整——需回执可对账；申诉被驳回不视为失败而是进入差异接受或再申诉评估。
- 恢复：冻结解除后从断点继续；Settlement Evidence Pack 版本化保留；平台结算规则更新后既有对账结论标记 `needs_revalidation`。

## 验收与经济性

- **产物验收**：Evidence Pack 结算原件/订单/退款/账务四源齐全率 100%；每个差异有归因分类与证据引用；GMV→净利桥接表科目完整；`unreconciled` 差异有跟进计划而非被忽略。
- **经营指标**：对账差异率、差异归因准确率（抽样复核）、差异追回率、关账周期、未解释差异余额、桥接表科目覆盖率。
- **双层 KPI 关系**：本场景是**所有 KPI 的事实基础**——FLOW-01 的 GMV、FLOW-09 的双层指标都以本场景的对账结论为准；差异未解释前相关指标标 `provisional` 不得对外引用。本 Case 不产生经营结论只产生财务事实。
- **经济性门槛**：首个周期以「至少一个完整结算周期对账闭环 + 差异归因抽样准确率达标 + 桥接表被 FLOW-08 复盘实际引用」为验收前提。
- **必须回放**：无法勾稽的差异被强行配平（应被 `unreconciled` 规则拦截）；汇率用单一口径掩盖双口径差异（应被币种规则拦截）；平台费用结构变更未更新费率版本仍对账（应被版本校验拦截）；桥接表遗漏退款准备金科目（应被科目完整性检查拦截）；AI 出具审计意见越权（应被职责边界拦截）。
