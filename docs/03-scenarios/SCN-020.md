# SCN-020：数据质量、知识、系统与 AI 运行

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-06（需求到数据产品与业务工具）绑定时为 AGT-047 接桥；FLOW-08（经营复盘与资源更新）绑定时为 AGT-001 衡远。依据：D-022~D-026、D-053、D-078、PB-006、PB-008。

适用说明：本场景是整个 AI 组织的**运行底座**——数据质量、知识资产、系统集成、AI 岗位运行四者合一。FLOW-06 绑定时 AGT-047 接桥对「口径、数据质量和工具闭环」负责；组织/资源层面经 `correlation_id` 关联 FLOW-08 Case。它是唯一直接管理 AI 系统自身健康的场景：岗位 Bundle 版本、Skill 契约、数据契约、运行实例状态都在此监控。AGT-046 清源（数据工程）、AGT-047 接桥（系统集成）、AGT-048 积知（知识治理）、AGT-049 稳行（Agent 平台）、AGT-050 门卫（安全权限）构成五人组。

## 经营目的与范围

把数据、知识、系统与 AI 运行转化为**可监测、可诊断、可修复的基础设施闭环**，让「数据可不可信、知识新不新、系统通不通、AI 跑没跑好」有据可查。

- 业务对象：数据质量（完整性/准确性/时效性/一致性）、知识资产（Playbook/Skill/案例/方法论的版本与有效性）、系统集成（API/连接器/数据管道）、AI 运行（岗位 Bundle/运行实例/任务队列/错误率/成本）；不含具体业务场景执行（各 SCN Case 消费本场景产物）、预算分配（SCN-001）、组织设计（SCN-019）。
- 范围内：基础设施信号监测 → 质量/知识/系统/运行诊断 → 修复建议 → Action Intent（数据修复/知识更新/系统变更/岗位版本发布）→ 执行回执核验 → 健康复盘。
- 范围外：不直接修改生产数据/系统配置/岗位 Bundle（当前无授权，全部 `NoActionRecord` 或 Action Intent）；不做业务分析（各 FLOW Case）；不做预算分配（SCN-001）；不做组织设计（SCN-019）；不做安全策略制定（AGT-050/AGT-044 负责策略，本场景监控执行）。
- 不适用：无数据契约或质量基线（先建契约再谈监控）；AI 岗位未实例化（运行监控降级为配置审计）。

## 触发与输入

### 触发

- 经营节奏：数据质量日检、知识资产周审、系统健康月检、AI 运行实时监控、版本发布前检查。
- 信号触发：数据质量指标跌破阈值、知识资产过期/冲突、系统集成故障、AI 岗位错误率上升/成本异常/任务积压、Bundle 版本不一致、安全事件。
- 结构触发：同一数据源多场景消费时质量问题放大、知识资产版本分裂、系统依赖链断裂、AI 岗位能力退化。

## 业务闭环

1. **STG-01 信号接收**：数据质量、知识资产、系统集成、AI 运行、安全事件分别建档；按影响面分级。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-06 为主，FLOW-08 关联不兼）、主场景 SCN-020、范围（数据源/知识域/系统/岗位/时间窗）、修复权限上限声明。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载基础设施诊断与修复 Skills；只读监控/日志/契约/运行工具；版本与依赖关系库。
4. **STG-04 证据与诊断**：五人组分别产出证据——AGT-046 数据质量报告、AGT-047 系统集成状态、AGT-048 知识资产健康度、AGT-049 AI 运行指标、AGT-050 安全审计；诊断定位根因（数据源问题/管道故障/知识过期/平台异常/权限漂移/配置错误）；评估业务影响面（哪些 Case/指标受影响）。
5. **STG-05 方案产物**：「基础设施行动包」——数据修复建议（重跑/回填/口径调整）、知识更新建议（版本发布/废弃/合并）、系统修复建议（重启/扩容/切换）、AI 岗位调整建议（Bundle 更新/实例重启/任务重排）、安全加固建议；每条标注影响面、回退方案与可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（契约符合、版本一致、依赖完整、权限最小、schema、回退方案存在）+ AGT-005 语义复核（根因是否有监控证据、修复是否考虑依赖链、影响面是否完整、安全建议是否过度或不足）。
7. **STG-07 受控动作**：获批方案拆为 Action Intent——数据修复任务、知识版本发布、系统配置变更、岗位 Bundle 发布、安全策略调整；当前阶段全部 `NoActionRecord` 或内部审批 Intent。
8. **STG-08 核验与关闭**：修复回执与健康指标核验（质量恢复/系统稳定/运行正常）；影响面复盘（哪些 Case 受益）；关闭后学习提取回流（哪些故障高频、哪些修复有效、哪些监控缺失）。

## 授权与例外

- **允许**：只读监控/日志/契约/运行数据；产出诊断、修复建议、Action Intent 与影响面分析；跨 Case 引用已验收 Artifact。
- **冻结条件**：监控数据不可用；契约/版本信息缺失；依赖关系不明；安全事件未定级；修复方案无回退路径。
- **高风险动作分级**：生产数据修改、系统配置变更、岗位 Bundle 发布、安全策略调整、权限变更——逐对象单独审批；AI 不得直接执行任何生产变更只建议。
- **歧义处理**：根因不明时标 `root_cause_unknown` 并扩大监控范围而非猜测；影响面不确定时标 `impact_uncertain` 并保守估计。
- **重复与部分失败**：同一基础设施问题跨 Case 重复诊断时关联既有 Case；部分监控源缺失时只冻结受影响维度；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；发现监控系统性失效；修复动作引入新故障；安全事件升级；AI 运行平台不可用。
- 冻结范围：仅冻结受影响数据源/系统/岗位；已执行的修复由执行 Case 管理，本 Case 只引用回执；**关键岗位 Bundle 发布失败时冻结该岗位全部 Case**。
- 已产生外部效果：数据修复、知识发布、系统变更、岗位版本、安全调整——需回执可对账；修复后问题复发的标 `recurring_issue` 进入根因再诊断。
- 恢复：冻结解除后从断点继续；Infrastructure Evidence Pack 版本化保留；契约/版本/依赖更新后既有诊断标记 `needs_revalidation`。

## 验收与经济性

- **产物验收**：Evidence Pack 五源齐全率 100%；每个诊断有监控证据；每个修复建议有回退方案；影响面评估完整；安全事件有定级与升级路径。
- **经营指标**：数据质量合格率、知识资产时效性、系统可用性、AI 岗位错误率/成本、任务积压时长、安全事件数、修复成功率、影响面最小化。
- **双层 KPI 关系**：本场景是**一切 KPI 的可信度前提**——数据质量决定指标是否可信（FLOW-06 关联），AI 运行质量决定 Case 产出是否可靠（全 FLOW 关联），知识资产时效性决定方法论是否过时（FLOW-09 关联）；本 Case 不背业务结果只对基础设施事实与健康负责。
- **经济性门槛**：首个周期以「基础设施健康仪表板建立 + 至少一次故障诊断与修复闭环 + 监控覆盖率达标」为验收前提。
- **必须回放**：根因不明强行归因（应被 `root_cause_unknown` 规则拦截）；修复无回退方案（应被回退检查拦截）；影响面漏评（应被影响面检查拦截）；安全事件未定级直接修复（应被定级规则拦截）；岗位 Bundle 发布失败未冻结该岗位 Case（应被冻结规则拦截）；监控数据过期仍作为诊断依据（应被时效校验拦截）。
