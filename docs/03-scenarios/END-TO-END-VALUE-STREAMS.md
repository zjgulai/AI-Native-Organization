# 12条MECE端到端价值流与双工作流

状态：产品与组织协作设计基线。结构化权威目录为[e2e-value-streams.json](e2e-value-streams.json)；Site只读取其发布投影，不是业务system-of-record。

## 1. 为什么是8 + 4

现有FLOW-01至FLOW-08保持不变，它们完整覆盖经营对象从增长到复盘的八种闭环结果。Magpie-Horch补充的不是新的业务部门，而是四种能力产品：岗位、Skill、连接器和Release。

| 价值流家族 | 数量 | 起点 | 唯一闭环结果 |
| --- | ---: | --- | --- |
| BVS业务经营流 | 8 | 经营机会、目标、需求或风险信号 | 业务结果、外部动作回执与经营约束核对 |
| CVS能力供应流 | 4 | 业务暴露的能力缺口或经批准的能力变更 | 可复用、版本化、经验证且可回退的能力产品 |

MECE边界：

- BVS-01至BVS-08按业务结果分割，不按传统部门分割；一张Case只选一条主业务流。
- CVS-01只回答“谁负责、按什么责任契约运行”；CVS-02只回答“需要什么知识和方法”；CVS-03只回答“如何安全连接和执行”；CVS-04只回答“哪个版本可重复安装、运行和回退”。
- 业务Case发现能力缺口时创建关联CVS Case。CVS交付后，原业务Case不能静默换版本；新Case显式固定新的Role Release Bundle。

## 3. 两种工作流如何共存

产品方案工作流回答“产品能力如何把输入变成用户可验收结果”，包括页面、数据、工具、外部系统和产物。分工协作工作流回答“谁以什么责任完成每次交接”，包括主责岗位、贡献岗位、独立保障与接收条件。

运行时仍遵循同一规则：

~~~mermaid
flowchart LR
    S[经营信号] --> C[Case Control唯一建单]
    C --> A[一个Case Agent<br/>一个主岗位人格]
    A --> K[按需加载岗位Skills与产物契约]
    K --> G[Acceptance与Assurance门禁]
    G --> I[Action Intent]
    I --> P[模型外Policy Gate]
    P --> E[Execution Broker]
    E --> R[业务系统回执与结果]
    R --> A
~~~

网站中的“产品方案”与“分工协作”切换是同一价值流的两个投影，不会创建两套流程状态。

## 4. 八条业务经营流

### BVS-01 存量GMV增长 / 存量GMV联营舱

- 产品方案：机会雷达 → 联合诊断 → 经营行动包 → 受控执行 → 增量归因。
- 分工协作：当前目标合同以AGT-023与AGT-003/045固定范围和口径；实际Case只按渠道装配一个渠道经营主人格及对应渠道Skill，候选责任目录覆盖AGT-021/022/023/024/025；增长岗位诊断，AGT-016组织供需约束，渠道主人格装配逐对象Intent，AGT-003与独立财务保障核对结果。当前不实例化Shopify Case；Amazon后续实例由AGT-021担任主人格。
- 关键边界：GMV不能突破预算、库存、价格、账号与合规护栏；无权威数据或回执时冻结对象。

### BVS-02 新品证据到商业验证 / 新品证据工厂

- 产品方案：证据入池 → 机会命题 → 样品与准入 → 最小商业验证 → 组合决策。
- 分工协作：用户研究与洞察岗位建立证据；AGT-008组织产品定义；研发、质量、供应与合规岗位交付外部实测；渠道增长岗位运行有边界实验；经营岗位决定继续、转向或停止。
- 关键边界：生成内容、模拟结果和文档评审不能替代实物、质量、临床或市场回执。

### BVS-03 供需补货与交付 / 供需履约控制塔

- 产品方案：需求真相 → 约束计划 → 承诺执行 → 履约跟踪 → 可售核对。
- 分工协作：AGT-016建立需求基线；采购、计划、财务和风险岗位给出约束；供应岗位形成逐SKU计划；物流岗位取得单据；经营与独立控制核对可售和资金事实。
- 关键边界：采购、预留、运输和资金动作只认权威业务单据；预测不能替代库存事实。

### BVS-04 新市场与合规上架 / 市场准入发布器

- 产品方案：市场可行性 → 准入矩阵 → 发布包 → 受控上线 → 首周期验证。
- 分工协作：AGT-024固定市场、渠道、账号和产品范围；产品内容岗位准备主数据；渠道岗位形成发布Intent；合规、财务与风控独立门禁；经营岗位复盘扩大、修复或退出。
- 关键边界：页面预览和工具成功不能替代平台可售、合规、履约和结算回执。

### BVS-05 客户旅程与复购 / 客户旅程修复台

- 产品方案：旅程信号 → 原因分群 → 修复方案 → 受控触达 → 体验学习。
- 分工协作：客服、VOC和社群岗位汇聚事件；AGT-034诊断客户任务；渠道、内容、产品与供应岗位形成修复包；受控渠道执行触达；消费者洞察和独立保障核对问题关闭与复购。
- 关键边界：重大质量与账号事件转BVS-07；退款、补偿和营销触达各自需要动作策略。

### BVS-06 需求到数据产品与业务工具 / 数据产品工作台

- 产品方案：需求契约 → 数据契约 → 工具产品 → 独立验收 → 运行改进。
- 分工协作：AGT-047与业务岗位定义决策任务；AGT-045维护权威口径；工程与Agent平台岗位交付Tool/API/UI；AGT-050及独立控制验收；业务结果负责人复盘采用和价值。
- 关键边界：本地任务板、页面和缓存不是system-of-record；写工具另需Access、Policy与Broker验收。

### BVS-07 质量与账号重大事件 / 重大事件控制室

- 产品方案：权威信号 → 范围与保护 → 受控处置 → 根因与整改 → 恢复与学习。
- 分工协作：AGT-018与质量岗位验证信号；模型外Guard或正常Case产生最小保护Intent；供应、渠道、客户和合规岗位处置；独立审计复核根因；恢复只凭正常策略和证据。
- 关键边界：Emergency Guard不能恢复、退款、召回、销毁、对外承诺或执行永久变更。

### BVS-08 经营复盘与能力组合 / 经营复盘与能力组合台

- 产品方案：证据账本 → 差距诊断 → 组合选择 → 版本化变更 → 周期核对。
- 分工协作：经营分析汇总同口径证据；经营、财务、法务和风险独立复核；组织与平台岗位诊断能力；能力治理岗位发布版本；AGT-001裁决下一周期。
- 关键边界：AI可形成组织与资源建议；招聘、解聘、薪酬、预算和公司策略仍需已配置企业动作策略。

## 5. 四条能力供应流

### CVS-01 岗位与场景产品化 / 岗位产品编译器

- 产品方案：责任源建模 → 五契约编译 → Preset生成 → 无损与风险评测 → Bundle发布。
- 分工协作：AGT-004接收责任变更；数据与能力治理维护契约；AGT-048/047/049编译装配；AGT-005/050独立保障；AGT-049注册版本，AGT-002只在新Case引用。
- 唯一产物：不可变Role Release Bundle。它不拥有Skill内容、连接器授权或发行环境。

### CVS-02 知识与Skill供应 / Skill供应链

- 产品方案：需求与来源 → 分类与恢复 → 内容工程 → 结果评测 → 绑定与退役。
- 分工协作：能力治理先区分知识缺口与工具/数据故障；研究岗位维护来源与适用性；Agent工程实现动态Skill；独立保障对照任务结果；发布或退役岗位绑定。
- 唯一产物：经任务结果评测的Skill Binding Release。安装、检索或路由命中本身不是验收。

### CVS-03 Tool、MCP与API连接 / 企业连接器工厂

- 产品方案：系统与动作契约 → 连接适配 → 工具UI → 控制集成 → 探针与运营。
- 分工协作：AGT-047与业务岗位定义任务；AGT-045和控制岗位定义数据/权限；工程岗位交付适配器和组件；平台与保障岗位验证Policy/Broker；业务岗位做目标任务验收。
- 唯一产物：Connector Acceptance Pack。凭据不进入模型，写能力不直接交给模型。

### CVS-04 Release与运行保障 / Release与可靠性控制塔

- 产品方案：候选冻结 → 确定性门禁 → 同源装配 → 原子安装 → 运行学习。
- 分工协作：AGT-049冻结范围；数据、工程、能力岗位运行技术门禁；经营、财务与风险复核任务结果；平台执行安装与回退演练；运行证据触发保持、隔离或回退。
- 唯一产物：可重复安装和回退的Release。快速Gate绿色只证明其明示覆盖范围。

## 6. 角色分工的机器约束

结构化目录对每条流维护role_scope和五个collaboration_workflow步骤。每一步区分：

- lead：该阶段产物的责任契约主责。
- contributors：通过Skills、数据或类型化产物提供输入的岗位。
- assurance：不能由主责自我替代的独立检查责任。
- handoff：下游接收该产物前必须满足的条件。

这些字段是责任视图。运行编译时，一个Case Agent按阶段装配对应能力，不启动lead、contributors和assurance所对应的多个自由对话Agent。

3. 通过CVS-03交付首批只读连接器、工具卡和真实探针。
4. 通过CVS-01/02生成样本岗位Bundle和经业务任务评测的Skills。
5. 通过CVS-04把角色无损、连接真实、业务任务、Policy/Broker和回执加入联合Release门禁；先Shadow，再Limited，只有经营、自治异常、全成本和回退证据满足条件时才讨论Production。
