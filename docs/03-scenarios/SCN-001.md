# SCN-001：经营目标、预算与资源分配

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-08（经营复盘、资源和组织能力更新）绑定时为 AGT-001 衡远；FLOW-01/FLOW-06 绑定时以该流结果负责人为准。依据：D-025、D-078、PB-008、AGENTS.md「GMV 第一优先级」。

适用说明：本场景是整个 AI 组织的**顶层调度器**——把经营目标分解为预算包与资源约束，再分配给各价值流/场景 Case。FLOW-08 绑定时 AGT-001 衡远对「资源与能力版本变更」负责；GMV 目标的执行验证经 `correlation_id` 关联 FLOW-01 Case，数据基础设施投入关联 FLOW-06 Case。设计红线：**AI 只提出分配建议与约束校验，不替经营层做预算拍板**——资源分配是经营取舍，证据完备性是 AI 的职责边界。

## 经营目的与范围

把经营目标转化为**有约束、有优先级、有回执的资源分配方案**，让「钱花在哪、人力投哪、AI 岗位容量怎么分」有据可查。

- 业务对象：年度/季度经营目标（GMV/利润/品牌资产）、预算包（广告/库存/人力/外包/AI 运行成本）、资源约束（资金/仓容/团队容量/AI 并发上限）、优先级排序规则；不含具体投放执行（SCN-011）、采购执行（SCN-006）、定价决策（SCN-010）。
- 范围内：目标信号接收 → 约束盘点 → 分配方案生成 → 约束校验 → Action Intent（预算审批/资源调拨）→ 执行回执核验 → 偏差复盘。
- 范围外：不直接批准预算或调动资源（当前无授权，全部 `NoActionRecord` 或内部审批 Intent）；不做经营分析叙事（AGT-003 明镜）；不做组织设计（SCN-019）；不做数据基础设施建设（SCN-020/FLOW-06）。
- 不适用：无经营目标版本或预算框架（先建框架再谈分配）；目标与约束互相矛盾且无裁决机制（先升级人工）。

## 触发与输入

### 触发

- 经营节奏：年度预算编制、季度资源调整、月度目标追踪、重大事件后的应急重分配。
- 信号触发：目标达成偏差超阈值、预算消耗异常（超支/ underspend）、资源瓶颈（资金/仓容/人力/AI 容量）、新机会涌现需重新排序、外部环境变化（汇率/关税/平台政策）。
- 结构触发：多目标冲突（GMV 增长 vs 利润率 vs 品牌投入）、预算包间此消彼长、AI 岗位容量不足以支撑 Case 并发。

## 业务闭环

1. **STG-01 信号接收**：目标版本、预算进度、资源约束、业务信号、AI 成本分别建档。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-08 为主，FLOW-01/06 关联不兼）、主场景 SCN-001、范围（目标层级/预算包/周期）、决策权限上限声明。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载资源分配与约束优化 Skills；只读财务/预算/业务/AI 成本工具；目标与约束版本库。
4. **STG-04 证据与诊断**：AGT-003 组织 Resource Evidence Pack（目标分解、预算现状、约束量化、业务需求信号、AI 成本结构、历史偏差）；诊断识别约束瓶颈、目标冲突点、历史低效分配模式；输出「若维持现状」的基准预测。
5. **STG-05 方案产物**：「资源分配建议包」——逐预算包分配建议（增/减/持平+理由）、资源约束调整建议、优先级排序、风险预警（哪些目标在现有分配下达不到）；每条标注目标贡献假设与可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（预算总额守恒、约束不突破、科目完整、schema、目标口径一致）+ AGT-005 语义复核（优先级是否前后一致、目标贡献是否有证据、是否隐藏了权衡取舍）。
7. **STG-07 受控动作**：获批建议拆为 Action Intent——预算调整申请、资源调拨申请、目标分解确认；当前阶段全部 `NoActionRecord` 或内部审批 Intent。
8. **STG-08 核验与关闭**：分配执行回执与实际消耗核验；目标达成偏差分析；分配有效性复盘；关闭后学习提取回流（哪些分配模式有效、哪些约束常被低估）。

## 授权与例外

- **允许**：只读财务/预算/业务/AI 成本数据；产出分析、建议、Action Intent 与约束校验；跨 Case 引用已验收 Artifact。
- **冻结条件**：目标版本缺失或过期；预算框架未建立；关键约束（资金/仓容/AI 容量）未量化；目标相互矛盾且无裁决规则；历史数据口径不可比。
- **高风险动作分级**：预算总额变更、跨部门资源大规模调拨、新增 AI 岗位/预算科目——逐对象单独审批；AI 建议不得越权表述为「决定」。
- **歧义处理**：目标冲突时并列呈现权衡不擅自取舍；数据缺失时标注 `constraint_unknown` 并降低建议置信度。
- **重复与部分失败**：同一预算周期跨 Case 重复分配时关联既有 Case 更新；部分数据源缺失时只冻结受影响预算包；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；发现预算总额被误算；目标版本更新导致既有分配全部失效；重大外部事件（汇率/关税/平台政策）要求紧急重分配。
- 冻结范围：仅冻结受影响预算包/目标层级；已批准的分配由执行 Case 管理，本 Case 只引用回执。
- 已产生外部效果：预算调整、资源调拨——需回执可对账；分配后目标偏差超预期的标 `allocation_miss` 进入复盘。
- 恢复：冻结解除后从断点继续；Resource Evidence Pack 版本化保留；目标/预算版本更新后既有分配标记 `needs_revalidation`。

## 验收与经济性

- **产物验收**：Evidence Pack 五源齐全率 100%；每个分配建议带目标贡献假设与约束校验；预算总额守恒校验通过；权衡取舍显式呈现；AI 建议与经营决策权边界清晰。
- **经营指标**：预算执行偏差率、目标达成率、资源利用率、AI 运行成本占比、分配建议采纳率、目标冲突裁决时长。
- **双层 KPI 关系**：本场景是**所有 KPI 的分配器**——品牌资产目标与 GMV 目标的预算权衡在此显式呈现；分配结果对品牌/GMV 的实际影响由各 FLOW Case 核算，本 Case 只对「分配是否有依据」负责。
- **经济性门槛**：首个周期以「至少一轮完整预算分配建议被采纳 + 预算守恒校验通过 + 目标冲突至少一次显式呈现」为验收前提。
- **必须回放**：预算总额不守恒（应被确定性校验拦截）；目标冲突被 AI 擅自取舍（应被权衡呈现规则拦截）；约束未量化仍给出确定性建议（应被 `constraint_unknown` 规则拦截）；AI 表述越权为「决定」（应被职责边界拦截）；历史不可比数据被用于基准预测（应被口径检查拦截）。
