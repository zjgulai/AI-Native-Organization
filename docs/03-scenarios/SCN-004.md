# SCN-004：产品定义、开发与质量

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-02（新品：需求证据到商业验证）绑定时为 AGT-008 拓新；FLOW-07（重大质量事件）绑定时为 AGT-018 质守。依据：D-025、D-026、D-078、PB-002、PB-007。

适用说明：本场景覆盖产品从定义到量产的全周期——需求翻译成规格、开发过程跟踪、质量问题反馈。本场景是「产品满足要求并反馈真实质量问题」的闭环：开发侧产出规格与验证证据，质量侧把真实问题（客诉聚类、退货原因、VOC 反馈）回流设计。FLOW-02 绑定时 AGT-008 拓新对「商业验证阶段的产品定义质量」负责；质量事故升级为重大事件时拆 `correlation_id` 关联的 FLOW-07 Case 由 AGT-018 负责。Momcozy 适用性高：吸奶器等电子产品的质量问题直接影响安全与品牌信任。

## 经营目的与范围

把产品定义、开发与质量转化为**有规格基线、有验证证据、有问题回流的产品闭环**，让「产品是不是用户要的、质量是不是达标的」有据可查。

- 业务对象：产品需求规格（PRD/规格书）、设计与工程变更（硬件/软件/结构）、验证测试（实验室/用户/场景）、量产质量（来料/过程/出货/市场）、质量问题反馈（客诉/退货/VOC 聚类）；不含产品机会评估（SCN-003 上游）、供应商选择（SCN-006）、市场准入（SCN-005）、客诉处理本身（SCN-015——本场景消费其 VOC 产物）。
- 范围内：需求翻译 → 规格基线 → 开发跟踪 → 验证证据 → 质量监测 → 问题分类与回流 → Action Intent（变更/停产/召回评估）→ 结果核验。
- 范围外：不直接操作 PLM/ERP/测试设备（当前无授权，全部 `NoActionRecord` 或 Action Intent）；不做供应商管理（SCN-006）；不做市场准入判断（SCN-005）；不做客诉回复（SCN-015）。
- 不适用：无 PRD 或规格基线的产品（先建定义再谈开发跟踪）；纯软件无硬件载体（降级为软件质量流程）。

## 触发与输入

### 触发

- 经营节奏：产品里程碑评审（定义/设计冻结/验证完成/量产放行）、月度质量复盘、客诉聚类升级。
- 信号触发：需求变更请求、测试失败、来料/过程不良率超标、市场质量投诉聚集、竞品质量事件对标、法规/标准更新影响既有设计。
- 结构触发：同一缺陷跨批次重复、质量问题与设计变更时间重叠、验证证据与市场表现背离。

## 业务闭环

1. **STG-01 信号接收**：需求变更、测试结果、质量数据、VOC 聚类、法规更新分别建档；质量信号与开发信号分流。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-02 为主，FLOW-07 关联不兼）、主场景 SCN-004、范围（产品/SKU/批次/项目）、质量与开发约束声明。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载产品定义与质量诊断 Skills；只读 PLM/ERP/测试/客诉工具；法规与标准版本库。
4. **STG-04 证据与诊断**：业务贡献方产出 Product Evidence Pack（规格基线、变更记录、测试证据、质量数据、VOC 聚类、法规要求）；诊断区分「需求未满足」（定义问题）、「设计缺陷」（工程问题）、「制造偏差」（供应链问题）、「使用环境」（场景问题）、「质量事件」（升级 FLOW-07）；建立需求-规格-测试-市场的追溯链。
5. **STG-05 方案产物**：「产品行动包」——变更建议（规格/设计/供应商）、验证计划（补充测试/用户验证）、质量处置建议（批次隔离/退货/召回评估）、回流建议（移交 SCN-003 立项复审/SCN-015 客诉话术/SCN-006 供应商改进）；每条标注证据引用与可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（追溯链完整、测试方法版本、法规适用、schema、变更影响范围）+ AGT-005 语义复核（归因是否有数据支撑、验证是否充分、召回建议是否过度或不足）。
7. **STG-07 受控动作**：获批方案拆为 Action Intent——变更单、停产指令、召回评估、供应商改进要求；当前阶段全部 `NoActionRecord` 或内部审批 Intent。
8. **STG-08 核验与关闭**：变更/处置回执与质量指标核验（不良率/客诉率/退货率）；追溯链更新；关闭后学习提取回流（哪类缺陷高频、哪类验证有效、哪些供应商质量稳定）。

## 授权与例外

- **允许**：只读 PLM/ERP/测试/客诉数据；产出诊断、变更建议、Action Intent 与追溯分析；跨 Case 引用已验收 Artifact。
- **冻结条件**：规格基线缺失或版本冲突；测试证据不完整；质量数据口径不一致；法规版本过期；VOC 反馈未脱敏（PII 风险）。
- **高风险动作分级**：停产指令、召回评估、重大设计变更、供应商更换——逐对象单独审批；AI 不得出具「产品安全」结论只出具证据与建议。
- **歧义处理**：质量问题无法归因时标 `untraceable` 并扩大证据范围而非猜测；多批次同现问题优先假设共同原因（设计/供应商/原材料）而非分别归因。
- **重复与部分失败**：同一产品/批次跨 Case 重复评估时关联既有 Case；部分数据源缺失时只冻结受影响维度；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；发现规格-测试追溯断裂；质量问题升级为重大安全事件；法规更新导致既有认证失效。
- 冻结范围：仅冻结受影响产品/批次/项目；已执行的变更/停产由执行 Case 管理，本 Case 只引用回执。
- 已产生外部效果：变更单、停产、召回评估、供应商要求——需回执可对账；召回建议被市场监管机构采纳的标 `regulatory_action` 升级 FLOW-07。
- 恢复：冻结解除后从断点继续；Product Evidence Pack 版本化保留；规格/法规版本更新后既有评估标记 `needs_revalidation`。

## 验收与经济性

- **产物验收**：Evidence Pack 四源齐全率 100%；需求-规格-测试-市场追溯链完整；每个质量归因有数据支撑；每个变更建议有影响评估；VOC 回流被下游 Case 实际引用。
- **经营指标**：需求满足率、测试覆盖率、来料/过程/出货不良率、市场客诉率、退货率、追溯链完整率、问题回流周期。
- **双层 KPI 关系**：本场景是**产品质量与品牌信任的交汇点**——质量问题直接损害品牌资产（FLOW-09 关联）；产品定义质量影响新品成功率（FLOW-02 关联）；质量事件升级 FLOW-07。本 Case 不背品牌结果但对质量证据负责。
- **经济性门槛**：首个周期以「至少一条完整追溯链建立 + 一次质量归因完成 + 一次变更或处置建议被采纳」为验收前提。
- **必须回放**：质量问题无追溯链强行归因（应被 `untraceable` 规则拦截）；测试证据版本过期仍作为合格依据（应被版本校验拦截）；VOC PII 未脱敏进入分析（应被隐私规则拦截）；召回建议无风险评估直接提交（应被高风险审批拦截）；多批次同现问题分别归因而非找共同原因（应被聚类规则拦截）。
