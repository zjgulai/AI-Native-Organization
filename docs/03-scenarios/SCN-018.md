# SCN-018：店铺账号健康与渠道规则变化

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-07（质量和账号重大事件）绑定时为 AGT-018 质守；FLOW-01（GMV）/FLOW-04（市场合规）绑定时以该流结果负责人为准（BVS-01 现为 AGT-023）。依据：D-026、D-078、PB-007、[品牌增长方法论](../06-playbooks/BRAND-GROWTH-METHODOLOGY.md) 第 4 节「渠道购买场」。

适用说明：本场景是唯一同时适用**常规八阶段协议**与 **D-026 Emergency Guard 快速通道**的场景——账号健康事件（突发绩效警告、政策违规通知、封号风险）按确定性规则命中且唯一 Case 绑定成立时，可由模型外 Emergency Guard 经 Policy Gate、原子建单 Outbox 和 Execution Broker 执行固定最小保护动作；建单前歧义只记 Pre-Case Exception。常规信号（绩效趋势、规则变更跟踪）仍走完整八阶段。SCN-018 绑定三条价值流：FLOW-07 管事件处置与恢复，FLOW-01 管 GMV 冲击评估，FLOW-04 管渠道准入合规——按 D-025 拆 Case，`correlation_id` 关联。

## 经营目的与范围

把账号健康风险转化为**可监测、可分级、可处置、可复盘的防护闭环**，确保渠道资产（尤其 Amazon，约占 GMV 80%）不因规则违规或绩效恶化而中断。

- 业务对象：Amazon Seller Central 账号（含 Brand Registry 保护）、Target/Walmart Marketplace、DME 保险渠道资质、社媒商业账号；不含商品本身质量问题（归 SCN-015→FLOW-07 另一 Case）、物流时效问题（归 FLOW-03/SCN-006）。
- 范围内：账号健康指标监测 → 违规/预警信号分级 → 证据核实与根因诊断 → 处置方案（申诉/整改/暂停动作）→ 逐对象 Action Intent → 恢复核验与复盘。
- 范围外：不直接登录卖家后台执行申诉或整改（当前无授权，全部 `NoActionRecord` 或 Action Intent）；不做产品质量改进（SCN-015 上游）；不做新渠道开通决策（SCN-005/FLOW-04 上游）。
- 不适用：无账号健康指标基线的新渠道（先建监测再谈预警）；单一渠道无历史违规记录且无规则变更（降级为常规监测）。

## 触发与输入

### 触发

- **应急触发（Emergency Guard 候选）**：账号停用/暂停通知、政策违规警告（listing/IP/评价操纵/定价）、Payment Account 健康告警、Brand Registry 投诉受理。
- **常规触发**：Account Health Rating（AHR）趋势、Order Defect Rate/Late Shipment Rate/Valid Tracking Rate 阈值逼近、差评率与 ODR 联动、平台规则更新公告、Listing 被跟卖/劫持信号、账号权限降级。
- **结构触发**：多渠道规则冲突（同一行为在 A 渠道合规 B 渠道违规）、申诉驳回后根因未消除的重复违规、整改动作与业务动作冲突（如停售清货 vs 账号健康优先）。

## 业务闭环

### 常规路径（八阶段）

1. **STG-01 信号接收**：健康指标按账号×指标聚合；预警信号、规则变更、跟卖信号分别建档；`flow07_candidate` 标记供 Emergency Guard 判定。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-07/FLOW-01/FLOW-04 选一）、主场景 SCN-018、范围（账号/指标/时间窗）、处置权限上限声明。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载账号健康诊断与申诉写作 Skills；只读后台指标/规则/工单工具；历史违规档案。
4. **STG-04 证据与诊断**：AGT-027 组织 Account Health Evidence Pack（指标快照、违规通知、时间线、历史申诉、相关业务动作）；诊断区分「真实违规」（我方动作导致）、「误判申诉」（平台规则解释空间）、「外部攻击」（跟卖/差评操纵）、「规则变更」（平台更新导致存量不合规）。
5. **STG-05 方案产物**：「处置行动包」——整改清单（listing 修改/库存调整/流程修正）、申诉草稿（含证据引用与平台规则条款）、暂停建议（高风险期冻结哪些业务动作）、恢复判定标准；每条标注可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（指标口径、规则版本、申诉要素完整性、schema）+ AGT-005 语义复核（根因是否消除、申诉是否承认平台判定合理部分、暂停范围是否过度）。
7. **STG-07 受控动作**：获批方案拆为逐对象 Action Intent → Policy Gate 判定 → Execution Broker 执行 → 逐对象回执（申诉已提交/listing 已修改/账号操作已执行）；拒绝/异常记入 Case Ledger。当前阶段无授权连接时全部 `NoActionRecord`。
8. **STG-08 核验与关闭**：平台回执与指标恢复核验；根因消除确认（非仅申诉通过）；复盘提取（哪类信号最早预警、哪类处置有效）；关闭后学习回流规则库。

### Emergency Guard 快速通道（D-026）

- **触发条件**：确定性规则命中（如 AHR 跌破阈值、违规通知类型=X）且唯一 Case 绑定成立。
- **执行序列**：Emergency Guard → Policy Gate 判定 → 原子建单 Outbox → Execution Broker 执行**固定最小保护动作**（如冻结关联促销/暂停高风险 listing/标记待人工复核）→ 事后补建完整 Case 走八阶段。
- **边界**：建单前歧义只记 Pre-Case Exception 不建单；Emergency Guard 不得执行恢复/扩大性动作；最小保护动作清单由 Policy Gate 预定义，模型不可扩展。

## 授权与例外

- **允许**：只读账号健康/规则/工单数据；产出诊断、处置方案、申诉草稿与 Action Intent；跨 Case 引用已验收 Artifact。
- **冻结条件**：账号健康指标口径版本不明；平台规则版本过期；申诉历史缺失导致无法判断重复违规；Emergency Guard 规则未发布或 Policy Gate 未配置最小保护动作清单。
- **高风险动作分级**：申诉提交（对外法律性承诺）、账号级操作（权限变更/资金释放）、大规模 listing 下架——逐对象单独审批；Emergency Guard 最小保护动作除外（但限预定义清单）。
- **歧义处理**：信号无法判定为真实违规/误判/外部攻击时记 Pre-Case Exception 并降级为人工复核；Emergency Guard 路径遇歧义立即中止转人工。
- **重复与部分失败**：同 `case_dedupe_key` 关联既有 Case；多账号同时告警时按账号拆分独立 Case；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；平台发出二次警告或升级处罚；发现处置动作引入新违规；Emergency Guard 连续误触发。
- 冻结范围：账号级事件冻结该账号全部业务 Action Intent（跨 Case 生效——账号健康优先于 GMV）；指标级事件只冻结受影响指标关联动作。
- 已产生外部效果：申诉提交、listing 修改、账号操作——需逐对象回执可对账；申诉驳回不视为失败而是进入根因再诊断；**账号被暂停期间已执行的促销/广告动作可能继续消耗**，需标记 `orphaned_action` 供财务对账。
- 恢复：平台确认恢复后从断点继续；Account Health Evidence Pack 版本化保留；恢复判定须包含「根因消除证据 + 观察期指标稳定」双条件，不得仅凭申诉通过。

## 验收与经济性

- **产物验收**：Evidence Pack 指标口径版本标注 100%；每个处置建议带规则条款引用与证据链；申诉草稿通过 AGT-005 复核；Emergency Guard 触发/中止/转人工记录完整。
- **经营指标**：账号健康指标趋势、违规事件数与严重度、申诉成功率、MTTD（平均发现时长）/MTTR（平均恢复时长）、因账号问题导致的 GMV 损失估算。
- **双层 KPI 关系**：本场景是 FLOW-09 品牌资产的**护栏场景**——账号中断直接摧毁所有品牌指标（流量/认知/复购归零），因此验收不看增长只看「未发生不可逆损失」；FLOW-01/04 绑定 Case 的 GMV/市场指标损失经 `correlation_id` 关联核算。
- **经济性门槛**：首个周期以「Emergency Guard 规则经 Policy Gate 签字 + 常规路径处置方案全部可对账 + 至少一次申诉或整改闭环完成」为验收前提。
- **必须回放**：Emergency Guard 对歧义信号建单（应被 Pre-Case Exception 拦截）；申诉草稿承认不存在的违规（应被证据链检查拦截）；账号暂停期间促销继续消耗未标记（应被 `orphaned_action` 规则拦截）；申诉通过即判定恢复（应被双条件恢复标准拦截）；跟卖信号被当作自家违规处置（应被根因分类拦截）。
