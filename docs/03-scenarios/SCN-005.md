# SCN-005：产品及市场准入、知识产权

状态：v1 设计规格；场景候选映射待企业验证。AI结果负责人：FLOW-04（新市场、新渠道与合规上架）绑定时为 AGT-024 拓域；FLOW-02（新品）绑定时为 AGT-008 拓新；FLOW-07（重大事件）绑定时为 AGT-018 质守。依据：D-025、D-078、PB-004、[品牌增长方法论](../06-playbooks/BRAND-GROWTH-METHODOLOGY.md) 第 4 节「出海」。

适用说明：本场景守护品牌域的两条边界——**市场准入边界**（哪些产品可以在哪些市场/渠道销售）与**知识产权边界**（品牌资产的法律防线）。IP 不是独立价值流而是横切治理：常规 IP 布局（商标/专利监测、listing 侵权处置）随本场景走八阶段；IP 争议升级为重大事件（专利诉讼、平台 IP 投诉导致下架）时拆 `correlation_id` 关联的 FLOW-07 Case 由 AGT-018 负责。Momcozy 适用性高：母婴品类监管密集（FDA/CPC/电气安全），Amazon IP 投诉与跟卖侵权是常态风险。

## 经营目的与范围

把「能不能卖、在哪卖、卖的东西是否侵权」转化为**有证据链的准入决策与 IP 防御闭环**，让市场扩张不越过合规与法律边界。

- 业务对象：SKU×市场准入评估、渠道上架资格（Amazon/Target/Walmart/DME/独立站各自要求）、商标/专利/外观设计布局与监测、平台 IP 投诉（侵权通知、跟卖假货、listing 抄袭）、认证要求（CPC/FCC/FDA 等）；不含产品功能定义（SCN-004/FLOW-02 上游）、日常 listing 内容优化（SCN-009）、账号绩效治理（SCN-018）。
- 范围内：准入信号评估 → 证据收集（法规/认证/IP 检索）→ go/no-go 建议 → 逐对象 Action Intent（上架申请/下架/投诉/认证提交）→ 回执核验 → IP 资产台账更新。
- 范围外：不直接向平台/监管机构提交申请或投诉（当前无授权，全部 `NoActionRecord` 或 Action Intent）；不做产品开发决策（SCN-004）；不做法务意见书（AI 产出证据与建议，法律判断由 AGT-043 确认）；不做市场进入商业论证（SCN-002/003 上游）。
- 不适用：法规要求未明确的品类-市场组合（先做法规检索再建 Case）；无 IP 检索工具基线（先建监测再谈主动防御）。

## 触发与输入

### 触发

- 经营节奏：新品上市前准入评审、季度市场准入复审、IP 资产年度盘点、平台规则/法规更新跟踪。
- 信号触发：新品立项通过（SCN-003 输出）、目标市场法规/平台政策变更、IP 投诉通知（我方被投诉或发现他方侵权）、跟卖/假货信号、认证到期、竞品专利公开。
- 结构触发：同一 SKU 多市场准入状态不一致、IP 投诉聚集于同一产品线、渠道准入要求冲突（A 渠道要求认证 B 渠道豁免）。

## 业务闭环

1. **STG-01 信号接收**：准入需求（新品/新市场）、IP 信号（投诉/侵权发现/规则变更）、认证到期分别建档。
2. **STG-02 建单**：Case Charter 固定主价值流（FLOW-04/FLOW-02/FLOW-07 选一）、主场景 SCN-005、范围（SKU 集合/目标市场/权利类型/时间窗）、决策权限上限声明。
3. **STG-03 上下文装配**：固定对应岗位 Release Bundle；装载准入评估与 IP 检索 Skills；只读法规/IP/平台规则/认证工具；目标市场法规版本库。
4. **STG-04 证据与诊断**：业务贡献方产出 Admission Evidence Pack（法规要求清单、认证状态、IP 检索结果、平台规则、竞品先例）；诊断产出三类结论——「可准入」（证据齐全）、「有条件准入」（需先完成认证/调整设计/获得授权）、「不可准入/高风险」（证据表明阻断）。IP 侧区分「我方权利受侵害」（主动维权）与「我方侵权风险」（被动防御）。
5. **STG-05 方案产物**：「准入/IP 行动包」——准入申请清单、认证办理路径、IP 维权/防御方案（投诉/授权谈判/设计规避建议）、权利布局建议（新申请/续展/放弃）；每条标注法律依据、成功概率评估与可证伪条件。
6. **STG-06 Assurance 门禁**：确定性校验（法规版本时效、IP 状态实时核验、认证有效期、schema、证据引用完整）+ AGT-005 语义复核（检索是否覆盖同族商标/近似专利、准入结论是否遗漏地方性要求、维权是否可能被认定恶意投诉）。
7. **STG-07 受控动作**：获批方案拆为逐对象 Action Intent → Policy Gate 判定 → Execution Broker 执行 → 逐对象回执（上架已提交/投诉已发起/认证已申请/权利已更新）；拒绝/异常记入 Case Ledger。当前阶段无授权连接时全部 `NoActionRecord`。
8. **STG-08 核验与关闭**：平台/机构回执与状态核验（上架成功/投诉受理/认证获批）；准入结果写入 SKU×市场矩阵；IP 台账更新；关闭后学习回流（哪些市场准入被低估风险、哪类 IP 投诉可批量处理）。

## 授权与例外

- **允许**：只读法规/IP/平台规则/认证数据；产出评估、申请建议、Action Intent 与权利台账更新建议；跨 Case 引用已验收 Artifact。
- **冻结条件**：目标市场法规版本缺失；IP 检索工具不可用且无替代证据；认证状态不明；准入决策涉及未决专利诉讼；平台规则版本过期。
- **高风险动作分级**：专利诉讼立场、跨境维权投诉、市场退出决策、认证豁免申请——逐对象单独审批；AI 不得出具「法律意见」只出具「证据与建议」。
- **歧义处理**：法规要求存在解释空间时标注 `regulatory_ambiguity` 并建议法务确认；IP 近似判断置信度不足时标注 `ip_uncertain` 并扩大检索而非直接结论。
- **重复与部分失败**：同 `case_dedupe_key` 关联既有 Case；多市场并行评估时按市场拆分子任务共享证据包；Worker 产物不合格退回 STG-04。

## 接管与恢复

- 停止条件：连续两轮补证不满足最小输入；发现已上架产品存在未评估的合规风险；平台发出 IP 投诉或下架通知；法规版本更新导致既有结论失效。
- 冻结范围**：仅冻结受影响 SKU/市场/权利类型；已执行的 Action Intent 由执行方 Recovery Contract 负责（申请可撤回、投诉可撤诉评估），本 Case 只引用回执。
- 已产生外部效果**：上架申请、IP 投诉、认证申请——需逐对象回执可对账；已提交的维权投诉被对方反诉的记 `counter_claim` 进入 FLOW-07 升级。
- 恢复**：冻结解除后从断点继续；Admission Evidence Pack 版本化保留；法规/IP 版本更新后既有准入结论标记 `needs_revalidation`。

## 验收与经济性

- **产物验收**：Evidence Pack 法规/IP/认证三类证据齐全率 100%；每个准入结论绑定 SKU×市场×法规版本；每个 IP 行动带权利状态核验与法律依据；go/no-go 建议与商业决策权明确分离（AI 给证据，商业方拍板）。
- **经营指标**：准入决策周期、IP 投诉响应时长、权利维护覆盖率、因合规/IP 导致的下架或损失事件数、认证到期及时率。
- **双层 KPI 关系**：本场景是品牌资产的**防御侧**——不创造认知但保护已建立的品牌资产不被侵权稀释或合规下架摧毁；市场准入结果对 GMV 的影响经 `correlation_id` 移交 FLOW-04/01 Case 核算。
- **经济性门槛**：首个周期以「至少一次完整准入评审闭环 + IP 台账建立 + 一次投诉或申请回执核验」为验收前提。
- **必须回放**：IP 检索只查英文商标漏掉中文近似（应被检索完整性检查拦截）；法规版本过期仍给出准入结论（应被时效校验拦截）；AI 直接出具「可销售」法律结论而非建议（应被职责边界拦截）；被投诉方反诉未升级 FLOW-07（应被 `counter_claim` 规则拦截）；多市场共用一份证据包但法规要求不同（应被 SKU×市场矩阵拦截）。
