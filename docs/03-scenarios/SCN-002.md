# SCN-002：市场、竞品与用户需求发现

状态：v1 设计规格（首个 FLOW-09 场景规格）；场景候选映射待企业验证。AI结果负责人：AGT-029 立言（FLOW-09 绑定时）；AGT-002 提供编排制度。依据：D-078、PB-009、[品牌增长方法论](../06-playbooks/BRAND-GROWTH-METHODOLOGY.md) 第 4 节「消费者洞察」、书2 第 9/10/12/13/24 章框架。

适用说明：本规格以 FLOW-09「品牌资产经营」为第一绑定场景书写；同一场景也可被 FLOW-01 等价值流按各自完成条件复用，但一张 Case 仍只绑定一条主价值流（D-025）。

## 经营目的与范围

把市场、竞品与消费者信号转化为**有依据、可证伪、可追溯的机会判断**，为品牌域决策（细分选择、内容方向、投放假设、市场进入）提供上游输入。

- 业务对象：品牌、品类、目标市场/渠道、竞品集合、消费者人群段；不含具体 SKU 定价或投放执行。
- 范围内：信号聚合 → 证据包 → 诊断记录 → 机会判断包（Decision Package）。
- 范围外：不发布内容、不调整预算、不改商品、不触达客户；所有外部动作只能以 Action Intent 形式移交下游场景（如 SCN-011 投放实验、SCN-012 内容生产）。
- 不适用：需要实时秒级响应的事件（走 FLOW-07）；纯交易履约异常（FLOW-03/04）；已明确的执行指令（不属于发现型场景）。

## 触发与输入

### 触发

- 品牌经营节奏触发：FLOW-09 季度/年度规划前的例行洞察 Case；
- 信号触发：品类搜索趋势异动、竞品 Listing/内容/广告重大变化、评论情绪拐点、社媒话题爆发、差评率越阈；
- 规划触发：新市场/新细分进入评估、品牌定义共创（书2 第 13 章）的前置研究。

### 输入

| 输入类 | 来源（候选，待确认接入） | 质量要求 |
| --- | --- | --- |
| VOC 原文 | 店铺评论、客服工单、退货原因、社媒评论/私信 | 原文级、带时间戳与渠道标识；去重后保留分布 |
| 行为信号 | Amazon 品类搜索词/BSR、独立站行为分析、广告搜索词报告 | 口径与 AGT-045 数据契约一致；标注归因局限 |
| 竞品证据 | 竞品 Listing、A+ 内容、广告素材快照、价格轨迹 | 截图/导出件带抓取时间；竞品集合须版本化 |
| 品牌基线 | 品牌资产指标现状（认知/声量/覆盖）、历史洞察 Case 产物 | 只引用已验收 Stage Artifact（REC-CROSS-CASE-ARTIFACT-REF） |
| 市场公开数据 | 平台行业报告、Google Trends 类公开指数 | 注明来源与时效；书中量化结论不得当作 Momcozy 实测 |

输入按「可分析 / 可触达」两级建档（书2 第 24 章）：Amazon 侧数据多为可分析受限、不可触达；独立站侧两者兼备。两级数据不混用同一结论口径。

## 当前基线

待企业验证。需在首次 Case 前补齐：各数据源的实际接入状态、历史任务量与峰值、人工洞察现状（耗时/成本/产出形态）、现有报表口径冲突清单。未补齐前，本场景按「证据完备性优先于时效」设计，不承诺 SLA。

## 责任与参与者

- **AI 结果负责人**：AGT-029 立言——对机会判断的质量与结论负责；判断须对照品牌定义/品牌理想版本（BRAND-GROWTH-METHODOLOGY §5）。
- **证据贡献**：AGT-006（消费者需求与 VOC 研究）、AGT-007（市场竞争与机会研究）——以 Worker 身份提供带来源的 ArtifactEnvelope；复杂 Case 经 Case Control 固定 Lead/Worker。
- **编排**：AGT-002 场景制度与 AGT-002/模型外 Case Control——建单、装配、门禁推进；AGT-002 不做业务判断。
- **数据契约**：AGT-045 业务口径与主数据——指标口径、对象映射、数据质量状态的唯一来源；口径冲突时冻结相关结论而非取平均。
- **独立复核**：AGT-005 内控审计与独立复核——检查证据链完整性、推断与事实分离、结论是否超出证据范围。
- **外部执行主体**：无（本场景不产生资产动作）；如需付费数据源，由策略与预算 Case 另行授权。

## 业务闭环

对应八阶段协同协议（COLLABORATION-GRAPH）：

1. **STG-01 信号接收**：信号源产生 Signal Envelope；品牌异常信号与例行节奏分别建档。
2. **STG-02 建单**：Case Control 生成 Case Charter——主价值流 FLOW-09、主场景 SCN-002、主岗位 AGT-029、业务范围（品牌/品类/市场/时间窗）与完成条件明确；`case_dedupe_key` 防止同信号重复建单。
3. **STG-03 上下文装配**：固定 AGT-029 Release Bundle；按需装载洞察类 Skills（见 P2 Skill 契约）、只读数据工具与品牌定义/理想版本；不向模型暴露凭据。
4. **STG-04 证据与诊断**：AGT-006/007 产出 Evidence Pack（来源、版本、新鲜度、冲突、缺口）；AGT-029 形成 Diagnosis Record——区分事实、假设、反证与不确定性；诊断框架对照方法论 §2 五认知与 §4 洞察环节。
5. **STG-05 方案产物**：形成「市场机会判断包」——候选细分/机会点、证据强度分级、建议的验证方式（指向下游场景）、所需数据缺口；每条结论标注可证伪条件。
6. **STG-06 Assurance 门禁**：确定性硬校验（schema、来源完整性、口径一致）+ AGT-005 语义复核（推断是否越界、量化结论是否误用书中数据）。
7. **STG-07 受控动作**：本场景通常为 `NoActionRecord`——产物移交下游；若判断包建议立项验证实验，仅输出 Action Intent 移交对应场景 Case（如 SCN-011/013），不在本 Case 内执行。
8. **STG-08 核验与关闭**：核对产物完整性与成本；Case 关闭后异步进入学习提取——被验证/被证伪的假设回流为品牌知识资产。

## 授权与例外

- **允许**：只读访问已授权数据源；产出结构化产物与 Action Intent；跨 Case 只读引用已验收 Artifact。
- **冻结条件**：数据源凭据/权限缺失；口径冲突未决；输入超出 Case Charter 范围；关键来源过期且无法补齐；推断依赖未批准的外部断言。
- **歧义处理**：建单前歧义记 Pre-Case Exception；范围内歧义在 STG-04 标注不确定性并缩小结论范围，不猜测填充。
- **重复与部分失败**：同 `case_dedupe_key` 命中直接关联既有 Case；Worker 产物不合格时退回 STG-04 补证，不降低验收标准。

## 接管与恢复

- 停止条件：连续两轮证据补齐后仍无法满足最小输入合同；或发现输入数据存在系统性口径错误（交 AGT-045/SCN-020 处理）。
- 冻结范围：仅冻结受影响的数据源/结论分支，其余结论可独立验收。
- 已产生外部效果：本场景无外部副作用，无需补偿；下游 Case 若已消费本产物，以 `REC-CROSS-CASE-ARTIFACT-REF` 记录版本与 Hash，版本更新时由下游 Case 自行判定是否重验。
- 恢复：冻结解除后从断点阶段继续；Evidence Pack 版本化保留，禁止覆盖历史证据。

- 产物约束：机会判断包每条结论带证据强度分级+可证伪条件；量化表述标注【实测/书中报告/假设】三级来源；
- 禁止项：发布内容/调预算/改商品/触达客户；外部动作仅 Action Intent 移交下游。

## 验收与经济性

- **产物验收**：Evidence Pack 来源齐全率 100%；每条机会判断带证据强度分级与可证伪条件；量化表述均标注「实测/书中报告/假设」三级来源。
- **经营指标**：洞察→决策转化率（判断包被下游 Case 引用比例）；假设证伪周期；单位洞察成本（token+工具+人力口径分列）。
- **双层 KPI 关系**：本场景不直接背负 GMV；其产物影响下游 FLOW-09/01 Case 的品牌资产与 GMV 结果，经 correlation_id 关联复盘，不单独归因。
- **经济性门槛**：单次 Case 成本须低于被替代的人工洞察等价成本的可验证口径；首次运行以「证据质量对齐人工基线」为验收前提，成本优化在第二阶段。
- **必须回放**：证据充分但结论被证伪（检查推断链）；数据口径冲突被静默取平均（应已冻结）；书中量化倍数被当作 Momcozy 实测引用（应被 Assurance 拦截）；Amazon 数据被当作可触达数据使用（口径违规）。
