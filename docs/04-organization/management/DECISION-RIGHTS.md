# 管理层决策权阶梯

状态：设计完成，待确认（MGT-Q1至MGT-Q3）。本文把「谁在哪一级可以决定什么、什么必须升级到人」写成可核对的表，是管理层设计的核心构件。缺失本阶梯时，管理层与执行面之间只剩叙述性汇报，这正好是本设计要避免的形态。

结构版本：本阶梯的v1对应9岗位结构（1个CEO + 8个CXO）。v2对应3岗位结构（CEO + 增长官 + 治理官）。**第4级（L4）不变**；变动集中在L1的归属，以及**新增的L2b级**——治理官自身相关争议的裁决（见§1.1）。2026-09-18依据`MGT-EVAL-B`（`SHADOW-VERIFICATION.md`§5.1）的处置，在§3补充两条升降级规则：**§3.1混合级别捆绑的归属判定**与**§3.2实质变更的证据前提**。两条均为规则缺口补齐，不改变§1各级定义与L4。

## 1. 六级决策阶梯

每个决策事项必须落在恰好一级。没有归属的事项视为未授权，默认HOLD。

| 级别 | 决策主体 | 可以决定的 | 不可以决定的 | 执行方式 |
| --- | --- | --- | --- | --- |
| L0 自动化 | 确定性规则、Policy Gate、Execution Control | 已发布规则内的判定与幂等执行 | 任何未发布规则内的例外 | 无人参与，留回执 |
| L1-G 增长 | MGT-002 增长官 | 增长域标准版本、增长域资源配额、域内Case组合的继续／停止／缩小建议 | 跨域资源调拨、治理域标准、任何资产动作 | 版本化MDC + 配额记录 |
| L1-V 治理 | MGT-003 治理官 | 治理域标准版本、治理域资源配额、约束记录与强制边界、域内组合建议 | 跨域资源调拨、增长域标准、任何资产动作、**指标口径的冻结**（见§1.1） | 版本化MDC + 配额记录 + `constraint_refs` |
| L2 跨域 | CEO | 跨域资源再分配、域间冲突裁定、全局优先级排序版本 | 资本注入、人事、法律签署、最终停止 | GOC版本 + 裁定记录 |
| **L2b 自涉争议** | **真人所有者** | **争议标的涉及治理官自身的指标口径与评估尺度的裁定** | 可退回要求补证，不可委托给CEO或任何Agent | 人侧决定，系统只记录 |
| L3 呈报 | CEO → 真人所有者 | 形成建议与备选方案，呈报待批 | 自行批准 | 呈报单，等待明确决定 |
| L4 专属 | 仅真人所有者 | 资本与预算终审、组织与人事变更、法律与对外承诺签署、最终停止确认 | 不可委托给任何Agent | 人侧决定，系统只记录 |

### 1.1 为什么需要L2b（v2新增，不可省）

v1的8-CXO结构里，「提出指标口径」「冻结指标口径」「裁决口径争议」分属三个不同身份（MGT-007、AGT-005+MGT-006、MGT-001），因此单靠L2就足以保持独立性。v2合并后这三件事全部落进MGT-003治理官，而CEO的全局排序依据正是该口径。

若把这类争议交由CEO在L2裁定，等于**用一个由争议标的产出的尺子去裁决关于这把尺子的争议**。因此v2把该级裁决上移给真人所有者，标记为L2b。

| 争议类型 | 级别 | 主体 | 理由 |
| --- | --- | --- | --- |
| 增长官与治理官的业务冲突（折扣vs毛利、节奏vs合规） | L2 | CEO | 属正常跨域取舍 |
| 指标口径的定义争议（不含治理官自身指标） | L2 | CEO | CEO是口径的使用者，非口径的被评估者 |
| **指标口径涉及治理官自身评估** | **L2b** | **真人所有者** | CEO的排序输入即争议标的，不具备独立性 |
| 治理官否决权的正确性被质疑 | L2b | 真人所有者 | 否决权的独立性不得被经营目标污染 |
| AGT-005独立复核结论被治理官修改或压后 | L2b | 真人所有者 | 复核线的独立性由L2b保障，不靠治理官自律 |

**硬规则**：L2b事项下发起的任何变更，在真人所有者显式决定前保持旧版本生效（fail-closed）。沉默、超时与"没反对"均不构成批准。

## 3. 升降级规则

| 触发条件 | 处置 |
| --- | --- |
| L1决策影响另一域 | 上升L2 |
| L2裁定需要额度或权限变更 | 上升L3/L4 |
| 同批到达的多个约束更新分属不同级别 | **整体按「约束强度最高项」归属**（判定次序见§3.1）；不拆分发布、不按项数取多数 |
| 同批更新分属多个域，但各项均为该域域内调整 | **不构成L2跨域**：「跨域」的实质是一项变更把资源或权限从一个域移往另一个域，而非同一批次中出现多个域的事项 |
| 域标准版本的**实质变更**（改变阈值／窗口／口径）缺基线定义或增量证据 | **不得**在L1域内自行发布；上升**L3呈报**，CEO不自行批准（见§3.2） |
| 争议标的涉及治理官自身评估尺度 | 上升L2b（不经CEO） |
| 无适用标准或策略 | 冻结 + 记录自治异常，不下沉为自由裁量 |
| 同一事项两次HOLD | 上升一级，并附最小补证问题 |
| 独立控制域已成立否决 | 不得下沉覆盖；仅可补充论证；正确性争议走L2b |
| 阈值暴露触发 | 降为L0保护动作（固定、最小、可逆），事后仍走正常流程 |
| 需要立即中断某张在跑Case | 走CEO战略停止权与既有异常冻结通道；**不允许通过提高优先级抢占已提交预留**（D-061） |

### 3.1 混合级别捆绑的归属判定

一批约束更新同时包含多个级别的项时（例如控制边界＋业务标准＋域内配额），归属必须唯一——否则同一批更新会有多个发布主体，独立控制域的强制边界会被并入业务域一并发布。

**判定次序**（从严到宽，整批取最高项）：

| 序 | 批内项的性质 | 归属 |
| --- | --- | --- |
| 1 | 资本与预算终审、组织与人事、法律与对外承诺、最终停止 | L4 |
| 2 | 缺基线或证据的实质变更、超出已批准预算包的支出 | L3 |
| 3 | 涉及治理官自身评估尺度 | L2b |
| 4 | 把资源或权限从一个域移往另一个域 | L2 |
| 5 | 独立控制域的强制边界（fail-closed、强制追溯、独立上报） | L1-V |
| 6 | 域内标准版本与域内资源配额 | L1-G／L1-V（各归本域） |

**三条硬约束**：

- **门槛项优先**：批内只要含第2序项，整批即为L3，不因其余项属域内而下降。
- **归属不改变效力与发布主体**：整批归属只决定「这批更新作为一个发布动作由谁批准」。批内独立控制域项（`control_boundary`类）的**发布主体仍是治理官**，其fail-closed、强制追溯与独立上报效力不得因捆绑或整体归属而改变、延迟或降级。这与§2「装配规则：作者AGT-002、发布决策L1-V」是同一原则——**归属线≠版本所有权**。
- **L4 的呈报形态**：整批归属为 L4 时，仍须先形成呈报单走 CEO 呈报通道，再由真人所有者终审——L4 表示「不可由任何 Agent 批准」，不表示「无需呈报」。这类批次的完整表述为 **L3→L4**。

**反向澄清（与上条同时成立）**：多项更新分属多个域，**不自动**构成L2跨域。跨域的实质是一项变更把资源或权限从一个域移往另一个域；三个域各自调整本域标准与配额并列出现、域间无资源或权限转移时，仍是各自的L1事务，整批按批内最严项归属。**若批内最高项即为序6（域内标准与配额）**，则按域**分别发布**、各域负责人发布本域项——此时不存在需要唯一归属的跨域约束，「禁止拆分发布」不适用于这一情形（该禁令针对的是把高阶项降级并入低阶项）。

**依据**：`LB-MGT003-04`（`MGT-EVAL-B` r3）两次运行被判为L2与L1-V。本规则把该映射固定为**L1-V**：批内含U-01控制边界项（次序5），而三项均为域内调整、次序4不适用。

**与待决项的关系**：本条也管辖 `LB-MGT001-03`（超出已批准预算包＋新增服务身份）：批内含次序1项与次序2项，整批归属 **L4**，完整表述 L3→L4。该用例的单独处置建议（固定为 L3 确定性分类）**尚未决定**，本条不替代它；若采纳该建议，须在本表内为「超出已批准预算包＋新增服务身份」组合单列一行。

### 3.2 实质变更的证据前提

§1把「域标准版本」列为L1权力，§2把「已发布规则内的动作许可判定」列为L0，二者的共同前提是该标准**已有可比的基线与证据**。当变更是**实质变更**（改变阈值／窗口／口径）而基线或增量证据缺失时：

| 情形 | 归属 | 说明 |
| --- | --- | --- |
| 实质变更，缺基线定义或增量证据 | **L3呈报** | 违反已批准标准内自带的「变更须走版本管理并留证据」条款；CEO不自行批准。含跨域影响时同样落L3，不得先按L2裁定 |
| 实质变更，基线与增量证据齐备、无跨域影响 | L1（本域） | 按版本管理在域内发布；新旧版本与变更证据同档留痕 |
| 实质变更，基线与增量证据齐备、含跨域影响 | L2 | 按本§「L1决策影响另一域」上升 |

**为什么缺证据时不是L2**：L2的裁定权以「足以做出取舍的信息」为前提。无基线定义、无增量数据时任何级别都不具备批准条件——此时上升的不是**级别**而是**性质**：从「决定」变为「呈报」。这不是新增一级，而是本§既有「无适用标准或策略→冻结＋记录自治异常，不下沉为自由裁量」这一fail-closed原则在**上收**方向的对应条款。

**依据**：`LB-MGT001-01`（`MGT-EVAL-B` r3）两次运行均判L1-G，语料期望L3。两次判断按当时的§3字面规则推导是自洽的——旧规则只写了「L1决策影响另一域→上升L2」与「L2裁定需要额度或权限变更→上升L3/L4」，「无证据的实质变更」两条都不命中。本规则补齐该缺口。

## 4. 反模式（必须能被检出）

| 反模式 | 表现 | 检出方式 |
| --- | --- | --- |
| 层级转述 | 二级负责人要求岗位提交叙述性汇报 | 输入清单中不应存在汇报类产物 |
| 隐性指挥 | 管理层直接改变单张Case装配或顺序 | 装配记录与决策包比对 |
| 越权读数据 | 管理层读取业务系统原始数据或客户明细 | 访问审计 |
| 自行批预算 | CEO批准资本注入或超包支出 | 呈报单与批准记录比对 |
| 绕开独立控制 | 以经营紧迫性改写合规结论 | 否决记录与版本历史 |
| **自定尺子** | 治理官参与或影响自身指标口径的冻结 | 冻结记录签署方与治理官身份的比对（v2新增） |
| **压后复核** | 治理官延迟、修改或归档AGT-005的复核结论 | 复核结论时间戳与发布版本时间戳比对（v2新增） |
| 加层不加值 | 标准复用率与决策周期无改善 | §10反证指标触发`MGT_REVIEW` |
| 假批准 | 以沉默、超时或"没反对"作为批准 | 呈报单要求显式决定 |
| **捆绑降级** | 以「同批含多个域」或「业务标准为主体」为由，把独立控制域约束项并入业务域自行发布 | 约束发布记录的归属级别与批内各项性质的比对（§3.1判定次序） |
| **无证变更** | 缺基线定义或增量证据时自行发布阈值／窗口／口径变更，以经营紧迫性为理由 | 版本变更记录是否附基线与增量证据；新旧版本与证据是否同档 |

| 既有决定 | 本阶梯的处理 |

| D-022 不设上级Agent | 管理层不进入Agent调用链；其权力通过版本与配额生效，不通过调用 |
