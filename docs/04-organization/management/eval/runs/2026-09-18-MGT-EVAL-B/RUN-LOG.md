## 0. 本门禁回答什么，不回答什么

`MGT-EVAL-B` 只回答一件事：**同一份输入、两次隔离运行，管理层的确定性决策是否稳定复现。**

它**不回答**「决定对不对」——本项目没有管理判断的正确性基线（`SHADOW-VERIFICATION.md` §3.1 已写明）。因此：

- **一致** → 该决策映射确定，可继续由模型层承担；
- **不一致** → 不是「模型不够好」，而是**该决策本不该由 LLM 承担**：应下沉为确定性规则（Policy Gate／MDC 字段），或上收为人类决策。这是本门禁最重要的用途——一条把「看起来像判断」的事项逐出模型层的流水线。

本台账同时记录**每一次重跑及其原因**，使「为什么重跑」可被独立核验；作废轮的原始输出逐字保存在 `voided-runs.json`，不删除、不筛选。

### 4.3 一致但偏离期望的项（门禁查不出，却更值得注意）

| 用例 | 两次运行 | 语料期望 |
| --- | --- | --- |
| `LB-MGT001-01` | L1-G（两次相同） | **L3** |

两次运行都判「属增长域标准变更，退回 MGT-002」，**稳定地偏离期望**。这一项顺利通过一致性检验，却与语料的设计意图不符。

它暴露的不是模型不稳定，而是**规范本身有缺口**：`DECISION-RIGHTS.md` §3 的升降级规则只写了「L1 决策影响另一域 → 上升 L2」与「L2 裁定需要额度或权限变更 → 上升 L3/L4」。「修改一个已批准的域标准版本、且无基线无证据」既不构成额度变更、也不构成权限变更，按字面规则推不出 L3。执行者按字面判 L1-G 是自洽的。

**这是本轮最重要的发现**：一致性门禁能发现「不稳定」，发现不了「稳定地按规则推导、而规则本身没写清」。后者要在 `DECISION-RIGHTS.md` 补规则，不能归咎于执行者。

## 5. 局限（必须随结果一起汇报）

1. **判分能力受限**：输出契约与语料期望的字段形态不完全兼容——`decision` 契约要求自由文本而语料期望为枚举，`must_detect`/`forbidden` 为自由标签，`queue_actions`/`availability`/`enforcement` 等结构化处置在契约中无对应字段。因此**只有 `ladder` 可客观精确比对**；「确定性子集一致率 ≥95%」这一门禁项本轮**无法独立评估**，不得以阶梯一致率冒充。
2. **隔离依据为执行者自述**：r3 的隔离由 prompt 硬边界声明 + 执行者主动声明共同保证，未做独立技术核验（无会话级读取审计）。
3. **执行者模型**：`deepseek-official` / `deepseek-flash`（reasoning effort `max`）。该值由运行结束后向执行者查证取得（其会话内无模型切换事件）。结论只在「该模型 + 该 prompt + 该语料」下成立，**不得外推到其它模型**——换模型是本门禁尚未覆盖的变量。
4. **全部输入为合成构造**：`corpus_provenance.limitation` 已声明——只能验证边界保持与决策稳定性，**不能证明业务判断正确**。真实经营异常、跨季度趋势与多市场差异均未覆盖。
5. **MGT-003 前提不满足**，见 §1.1。
