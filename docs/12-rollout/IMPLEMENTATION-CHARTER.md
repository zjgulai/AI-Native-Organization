# AI组织变革实施章程

状态：战略框架v1.1已确认；尚未授权真实账号写入、对外发送、采购/退款/预算操作、人员调整或生产发布。

## 已确认的实施方向

1. 以50种长期AI岗位、8个责任域和8条跨职能流程组织工作；实际工单只唤起必要岗位。
2. GMV为第一优先级，原始GMV、取消退款和经营约束分开呈现，避免用单一增长数字掩盖质量、现金或产品风险。
3. 50个Agent按场景动态匹配，自主完成正常经营闭环；初始不设置真人负责人或HITL为常规节点。
4. Agent可通过MCP、native tools、API和hooks连接系统，工具UI/UX可成为主要工作入口。
5. DeepSeek Harness负责AI执行；业务控制层或受控业务系统负责工单、动作策略、幂等、回执、自治异常与恢复。
6. 存量GMV经营和新品验证并行；真实的首个新品机会和验证资源后续确认。

这些方向对应[决策D-011至D-019](../00-project/DECISIONS.md)和[总体方案](../02-strategy/BLUEPRINT.md)。这不是自动裁撤、立即改变部门汇报关系或允许生产写入的决定。

## 首个经营样本的目的

首个样本的目的不是展示50个Agent同时工作，而是证明一个真实经营闭环能在明确范围、可信数据、动态编队、受控工具、外部回执和自治异常机制下运行。建议选择Momcozy可穿戴式吸奶器在一个已选市场的Amazon范围，以FLOW-01存量GMV经营为主线，FLOW-06提供同一范围的数据和工具；FLOW-02先产出新品验证设计。

实际市场、账号、SKU集合、数据质量和是否存在重大质量/库存事件由R04-Q1确认，不能由本章程假定。

## 阶段门

| 阶段门 | 必须形成的实物 | 不允许跳过的判断 |
| --- | --- | --- |
| G0：样本与环境 | 业务范围、AI结果负责人、GMV口径、约束、数据源、目标Harness事实、工具能力登记册 | 样本是否小到可控、又足以代表真实经营协同 |
| G1：受控读取 | 数据契约、服务身份范围、工单/产物记录、跨范围拒绝验证 | 指标、账号与商品映射是否可信，读取是否越权 |
| G2：影子闭环 | 同一真实信号下的AI行动包、旧方法对照、编队/工具/异常记录 | AI是否能发现广告、价格、库存与约束冲突，而不产生副作用 |
| G3：有限自主动作 | 经明确策略允许的动作类型、幂等、回执、补偿和冻结安排 | 写入是否可核对、可停止、可恢复，且不突破经营约束 |
| G4：扩展决定 | 经营结果、自治异常负荷、全成本、峰值和恢复证据 | 能否扩大商品、账号、市场或动作范围 |

每一阶段都可停止或回到上一阶段。G3不是由文档批准自动触发，必须有具体业务范围、工具和动作策略。

## 五条实施工作线

| 工作线 | 最小交付 | 责任边界 |
| --- | --- | --- |
| 场景自治 | 样本目标、范围、编队、行动包、验收和异常流程 | AI结果负责人对工单结果负责；AGT-002对编队和状态负责 |
| 数据与度量 | 指标定义、对象映射、数据质量、基线和对照记录 | 数据契约定义语义，工具只读取允许范围 |
| 业务控制 | 工单状态、动作策略、预算占用、幂等、回执和异常账 | 真实动作必须在服务端或目标系统规则内校验 |
| Harness资产 | 版本化岗位、技能、Playbook、工具适配、tool UI和运行记录 | 仅在目标版本/schema已核实后生成配置 |
| 能力整合 | 193/46能力盘点、映射、评估与重复治理 | 50岗位是唯一长期责任身份，不直接删除既有能力 |

## 自主运行的成功证据

首个样本至少留下：同口径基线、AI行动包、动态编队记录、策略允许/拒绝、请求与外部回执、GMV与约束结果、自治异常/恢复、模型与工具成本、外部执行成本和能力版本。

管理层据此决定是否扩大，不以聊天量、Token数、Agent数量或UI截图代替经营证据。未来如启用HITL，再单独记录真人介入原因、时长、结果和是否可由策略/工具消除。

数值目标、观察窗口、具体工具和人员安排在[R04](../01-discovery/interviews/R04-autonomous-runtime.md)确认后补充；本章程不虚构预算、期限或省人比例。
